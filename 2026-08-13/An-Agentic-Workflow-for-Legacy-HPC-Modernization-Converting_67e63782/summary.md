# 论文速读：An-Agentic-Workflow-for-Legacy-HPC-Modernization-Converting

## 一句话总结
本文提出一种受监督的智能体（Agentic）工作流，将 GAMESS 量子化学软件中 56,448 行、225 个子程序的 Fortran 77 电子积分核心自动转换为 Fortran 2008，在 612 次测试运行中实现零化学相关差异的逐位（bit-for-bit）复现，并将自动化边界与失败模式进行了系统刻画。

## 研究问题与动机
- **遗留科学代码体量巨大，转换工作停滞**：计算科学中大量 Fortran 77 代码因体量过大而未升级，转换本身机械但工程量大，导致维护债务累积。
- **正确性验证是委托的核心瓶颈**：量子化学内核出错不一定崩溃，而可能是 SCF 能量第 12 位小数出现静默偏差并传播至多年后发表的成果，因此验证能力决定了安全委托的上限。
- **既有自动化工具无法处理语义理解任务**：基于规则的 Fortran 重构工具能完成机械转换，但无法诊断循环依赖、推断变量类型、编写有域特征的单元测试，也无法从自身引入的缺陷中学习制定新规则。
- **科学软件的领域特性未被充分利用**：GAMESS 提供了 49 个标准测试并视输出为规范值（canonical），其内置的精确验证能力远超一般软件工程场景，为逐位复现验证提供了天然基础。

## 核心贡献（创新点）
1. **设计了三层角色（转换/测试/审查）的智能体工作流，规范文档由智能体自行编写与修订**：与既有 LLM 代码转换工作不同，本文规范（CLAUDE.md / STYLE_GUIDE.md / AGENT_GUIDE.md）由系统自身迭代维护，知识沉淀于可 diff、可回退的版本化文本而非模型记忆。
2. **明确区分了机械转换与理解依赖型转换，并证明智能体的真正价值在于后者**：规则工具能完成形式转换（固定格式→自由格式、符号替换），但在 IMPLICIT NONE 类型推断、控制流重构、跨文件架构推理（如 eftei 家族的 USE 语句放置）等理解任务上会失败。
3. **实现了以精确数值复现为验收标准的完整闭环验证体系**：通过合成单元测试（255,000 个 shell quartets）+ 51 项集成测试（49 个标准测试 + 2 个补充测试）+ Jenkins CI，逐位复现至第 12 位小数，相比既有工作普遍采用容差带（tolerance band）验收有本质区别。
4. **经验性地刻画了自动化边界，识别出三种缺陷类及各自的发现机制**：编译器捕获类（接口/字面量错误）、逃逸类（ISHFT packed-label 类型错误）、共同模式盲区（构建配置不一致导致的 golden 过期），揭示了安全委托的实际可达范围。
5. **在单次会话中 7 小时 29 分钟完成 12 文件转换，平均每文件约 37 分钟**：证明了按文件独立转换的可行性，且时间成本随文件数量线性增长而非规模增长。

## 方法详解
- **三角色隔离工作流**：转换角色（conversion role）读原始 .src 文件、写出 .f90 文件、变更日志、单元测试驱动和 golden 输出；测试角色（testing role）独立 worktree 编译 F77/F90 双版本并对比结果，设计补充数值测试；审查角色（review role）执行表 I 中的 9 项风格合规检查并报告结果。三者通过共享仓库协作，互不干扰。
- **四文档规范体系**：CLAUDE.md 定义工作流契约（每次会话自动加载）；STYLE_GUIDE.md 定义转换规则；AGENT_GUIDE.md 持有角色提示词、编译器不变量和限制说明。三文档均由智能体编写，并经历至少两次修订（如精简上下文大小、新增审计规则以消除已发现缺陷类）。
- **转换约束（Envelope）**：自由格式 132 列源文件、全局 IMPLICIT NONE、REAL(real64) 类型、所有 dummy 参数标注 INTENT、结构化控制流（替换 GO TO 和算术 IF）、每个文件一个 MODULE、COMMON 块保留原样并加注 deferral annotation。**明确禁止算法重构**（浮点重排、循环融合、向量化），以确保精确等价。
- **逐文件转换循环**：分支→读取原始文件→编写现代化源码/变更日志/驱动→按顺序编译模块依赖→编译 F77 原始并捕获 golden→在 -std=f2008 下编译现代化源码并 diff golden→用替换后的文件重建完整 GAMESS 二进制并运行全部测试→提交人工审查。
- **合成单元测试**：每个文件附带一个单元测试驱动（图 1 示例），同一源码分别以 -DUSE_MODULE 和不使用该宏编译两次（前者链接 F90 模块，后者链接 F77 原始），固定种子（ISEED=17）确保确定性，约 255,000 个合成壳 quartets 参与验证。
- **两级集成验证**：第一级对 51 个测试输入做 bit-for-bit 比较（过滤时间戳、主机名等，仅保留能量、迭代轨迹、核排斥能、virial 比、梯度等化学相关内容）；第二级使用 GAMESS 维护者的 Jenkins CI 套件（容差基准）。
- **智能体自审计**：要求每个文件对 ISHFT 基 packed-label 构造进行差异化计数，确保现代代码与原始在位操作调用数、packed-label 数组参数数、写入子程序数上完全一致。

## 实验与结果
- **数据集**：GAMESS 电子积分核心（ERI）12 个源文件，共 56,448 行 F77、225 个子程序，涵盖 int2 和 eftei 两个家族。
- **评估基线**：GAMESS 官方 49 个标准测试 + 2 个补充测试（cc-pVQZ 水分子计算，角动量 L=3；HCl 标量相对论 DFT，最昂贵单测试约 15 分钟）+ Jenkins CI 套件。
- **主要结果**：
  - 12 个文件全部通过 51 项标准测试和 Jenkins 测试，**612 次测试运行中化学相关差异数为 0**。
  - 聚合代码行数几乎不变（56,448 → 55,916，-0.94%），子程序数完全保留（225 个）。
  - 12 个文件中 11 个首次转换即数值正确，11 个首次编译即干净。
  - 唯一逃逸缺陷：ISHFT packed-label 构造中 `REAL(real64) :: IX(*)` 应改为 `INTEGER(int64)`，由标准化构建标志 `-fdefault-integer-8` 后 golden 重新生成暴露。
  - 智能体通过二分法定位该缺陷（38 个子程序中 5 轮收敛），编写 113 行 Python 二分测试工具，并将通用审计规则写入 STYLE_GUIDE.md。
- **最强结果**：在 56,448 行、1,066 个 COMMON 块、718 个 GO TO 语句的复杂代码库上实现零化学差异的 bit-for-bit 复现。

## 相关工作脉络
1. **Psi4（C++ 重写）**：从 Fortran 全面重写为 C++，属于跨语言重写而非同语言演进，与本文 F77→F2008 的同语言语义保留转换形成对比。
2. **NWChem（增量迁移）**：保持 F77/F90 混合表面并渐进迁移热点循环，采用容差带验收，与本文的精确验收和全量自动化方法不同。
3. **Rule-Based Fortran 重构工具（plusFORT/SPAG）**：可完成机械格式转换，但无法处理语义理解、循环依赖推理和自缺陷学习，本文划清了两类任务的边界。
4. **Fortran2CPP / Kokkos 移植类工作**：跨语言/跨架构移植，数值行为可重新表达，而本文强调 in-language、semantics-preserving 的精确等价转换。
5. **SWE-bench**：以小规模自包含程序为评估单位，以功能正确性为验收标准，而本文在百万行调用图中单个文件修改、以第 12 位小数差异为失败判据，验证严格度完全不同。
6. **Trilinos 项目**：HPC 领域最接近的先例，但采用与历史输出比较并允许容差的方式，本文设容差为零，使验收判定机械可解。

## 局限性与未来方向
- **范围局限**：仅覆盖了 GAMESS 百万行代码中的 12 个文件（ERI 核心），完整 PACKAGE 的转换尚未开展；COMMON 块迁移因跨文件共享特性未在本研究中解决。
- **验证覆盖不完整**：仅验证了标准测试和 Jenkins 测试集，GAMESS 提供的扩展测试套件尚未验证。
- **硬件平台局限**：全部测试在桌面工作站运行，未在 HPC 集群上验证。
- **工具与模型局限**：仅使用 Anthropic Claude Code 运行时和四代 Claude 模型（Opus 4.6/4.7/4.8、Sonnet 4.6），未在其他 agent 运行时或模型族上测试。
- **依赖领域验证能力**：该方法依赖于 GAMESS 已有的精确测试基准，缺乏类似验证 oracle 的代码库可能不适用此工作流。
- **未来方向**：将转换扩展至完整 GAMESS 代码库、集成至生产版本、迁移 COMMON 块为 MODULE、在 HPC 集群上运行验证、扩展至其他科学软件包。

## 研究启发与可借鉴点
1. **规范即产物（Specification as Durable Artifact）**：将知识沉淀于版本化文本（CLAUDE.md / STYLE_GUIDE.md）而非模型会话记忆，使方法具有可审计、可复用、跨模型可移植的特性，对任何需要长期维护的智能体编码项目均有参考价值。
2. **差分验证的共同模式盲区警示**：当 golden 和待测代码使用相同构建配置生成时，差分检查对系统性构建偏差完全不可见——这提醒我们在任何"自举验证"设计中必须保留一个外部锚定层（如维护者提供的 CI 基准）。
3. **严格编译标准作为低成本第一道防线**：启用 -std=f2008 而非 -std=legacy 可在零额外成本下捕获接口不匹配和字面量格式错误，这一策略对任何 Fortran 现代化工作具有普遍适用性。
4. **按文件独立转换的可行性**：尽管游戏引擎/大型科学代码通常无法原子性转换，但通过 MODULE wrapper 剥离和 USE 语句注入策略，单个文件的逐文件现代化是可行的，为大规模代码的渐进式升级提供了可行路径。
5. **缺陷类审计规则自动生成**：智能体在定位单个缺陷后，不仅修复了当前问题，还将泛化规则写入 STYLE_GUIDE.md，使后续所有文件自动受益于该审计——展示了"从个体缺陷到系统改进"的自提升机制。

## 关键术语表
- **Bit-for-bit reproduction**：逐位复现，要求现代化代码的输出与原始代码输出在最后一位小数上完全一致，零容差。
- **Golden output**：从原始 F77 构建捕获的参考输出，作为精确验证的基准。
- **ISHFT-based packed-label**：使用移位操作将多个壳层索引打包进单个 64 位字的技术，本文中发现的类型错误在此类构造上发生。
- **eftei family**：指 eftei、eftei_eric、eftei_genr03、eftei_genr70 四个文件的集合，构成 GAMESS 中电子积分的分发器。
- **IMPLICIT NONE**：Fortran 要求显式声明所有变量的语法约定，现代化过程中需对每个隐式类型变量进行类型推断。
- **DEFERRAL ANNOTATION**：对保留不变的 COMMON 块添加的显式标记，使跳过迁移决策的过程可机械审计。
- **Worktree**：Git 的独立工作目录机制，使多个智能体角色可并行工作而不互相干扰。
- **Tolerance band**：允许输出存在一定数值偏差的验收策略，与本文采用的零容差逐位复现形成对比。
