# 论文速读：From-Safety-Documentation-to-Safety-Knowledge-Support-An-Evi

## 一句话总结
本文针对医疗器械开发中文档密集、强合规与全生命周期追溯的需求，提出了一种基于证据的 LLM 支持框架，将研究范式从“自动生成安全文本”转向“源链接安全知识库支持”，通过证据接入、可控检索、方法特定生成、批判性检查与专家记录式审核的闭环流程，辅助安全工程师维护可追溯、可审查、可迭代的安全 artifacts。

## 研究问题与动机
1. **合规与追溯成本高昂**：医疗器械须遵循 ISO 14971 与 IEC 62304，安全分析贯穿需求、设计、验证、投诉与上市后数据全生命周期，高度依赖稀缺的安全与领域专家，企业（尤其中小企业）负担沉重。
2. **现有 LLM 方法缺乏监管适配性**：当前研究多聚焦孤立任务、依赖通用提示或公开案例，缺少对源文档链接、可追溯性、不确定性处理、生命周期变更联动及专家审查记录的体系化支持，难以满足受监管场景的审计要求。
3. **领域知识私有性与评估污染风险**：关键安全证据（需求规格、设计文档、验证报告、投诉记录）通常不在公开训练语料中；使用公开基准易造成评估数据与模型训练集重叠，且传统 NLP 指标（如 BLEU）无法衡量安全 artifact 的正确性与追溯质量。
4. **联网与 AI 化设备引入动态风险**：现代医疗器械融合传感器、嵌入式软件、云服务与 AI 模型，行为受训练数据、运行条件与输入分布变化影响，安全证据必须在发布后持续维护并响应现场反馈（如 TruDi 案例所示）。

## 核心贡献（创新点）
1. **重构问题范式：从“安全文本生成”到“源链接安全知识库支持”**：明确 LLM 的角色是辅助专家准备、链接、检查与更新候选安全项，而非替代专家做出安全性判断或监管审批。
2. **提出证据 grounded 的闭环支持框架**：设计了涵盖证据接入、安全知识与检索存储、任务设定、方法特定生成、批判与不确定性检查、专家审核与生命周期更新的完整流程，强调人工介入、审计追踪与版本管理。
3. **定义“源链接安全项（Source-linked Safety Item）”标准数据结构**：提出包含 ID、类型、设备链接、源证据、生成陈述、理由、假设、不确定性标记、审核决策、理由说明与变更历史的最小化可审查工件，使生成内容具备可追溯性与可更新性。
4. **构建面向监管场景的评估策略与指标体系**：主张使用非公开或新建案例规避数据污染，引入专家参考分析，并定义覆盖率、正确性、相关性、去重率、源支持度、不可支持声明率、追溯率、审查工作量与有用性等 9 项安全专用评估指标。
5. **系统梳理并分类 LLM 辅助安全工程研究现状**：基于 90 篇文献（2023–2026）按安全任务与主导 LLM 方法进行二维分类，识别提示词探索、检索增强、知识图谱、多智能体流水线、LLM 批判者五大研究模式，精准定位当前工作在医疗器械合规场景下的空白。

## 方法详解
框架以**源链接安全项**为核心流转工件，由以下组件协同构成（非分层架构，而是流程-工件接口驱动）：
- **证据接入（Evidence Intake）**：采集产品描述、预期用途、需求、软硬件设计文档、用户信息、风险管理文件、验证证据、投诉与上市后报告及相关标准。严格保留文档身份、版本、来源、日期与 artifact 类型，确保后续生成可回溯至具体版本的原始证据。
- **安全知识与检索存储（Safety-knowledge Storage and Retrieval）**：采用向量数据库、知识图谱、结构化表格或混合形式。检索不仅返回文本片段，还返回 artifact 标识符、版本号、章节位置与关系类型，为追溯与更新分析提供结构化基础。
- **任务设定（Task Setup）**：明确分析对象、系统边界、预期用途、使用环境、用户/患者上下文及选定的安全分析方法（FMEA 用于组件级故障、STPA 用于不安全交互、FTA 用于顶事件推理、Assurance Cases 用于结构化论证、ISO 14971 提供风险管理上下文）。
- **方法特定生成（Method-specific Generation）**：基于任务设定与检索证据，由 LLM 生成候选安全项（危害、危险状态、故障模式、原因、效应、风险控制、安全需求、验证思路等）。生成过程强制绑定证据链接，并记录需专家审查的隐含假设。
- **批判与不确定性检查（Critique and Uncertainty Checks）**：在专家审核前运行，检测重复项、格式一致性、逻辑矛盾、源证据支持度不足、多模型输出分歧等，生成 defeaters（反驳/质疑点）或审查问题，聚焦专家注意力于高风险、弱支持或冲突项。
- **专家审核与生命周期更新（Expert Review and Lifecycle Updates）**：合格安全工程师 inspect 源证据后对候选项做出 Accept/Reject/Edit/Merge/Split 决策并记录理由。当需求、软件、设计、验证结果、投诉或上市后数据变更时，框架自动检索受影响的安全项，提议更新草案，并触发重新审核，实现全生命周期闭环迭代。
