# 论文速读：JieZi: A Large-Scale Expert-Audited Dataset and Benchmark for Ancient Chinese Character Exegesis

## 一句话总结
本文首次将古代汉字训诂（ACCE）形式化为视觉-语言问答任务，构建了一个包含约50万专家审核QA对的训练数据集JieZi-Dataset和一个近8千专家逐条核验的评估基准JieZi-Bench，填补了古代汉字多维度综合分析研究在数据集与评测基准上的空白。

## 研究问题与动机
1. **现有工作局限于单点子任务**：已有研究主要聚焦于古文字识别、图像检索或单一标签分类等碎片化任务，未能覆盖完整的学者级训诂工作流程。
2. **通用多模态大模型缺乏领域知识且易幻觉**：现有MLLM在古文字分析中频繁出现事实性错误，而高质量的专业标注成本极高，全自动生成又可靠性不足。
3. **缺乏系统性的综合评测基准**：当前基准要么不含古文字图像，要么仅评估单一脚本类型的识别准确率，无法衡量模型在字形分析、语义阐释、历时演变等深层训诂能力。
4. **高质量多类型、多维度数据缺失**：已有数据集多为单一脚本（如甲骨文），且标注稀疏；缺乏覆盖多字期、多维度并经过专家审核的自然语言解释数据。

## 核心贡献（创新点）
1. **形式化ACCE任务**：首次将古代汉字训诂分解为四个递进层次（基础识别、字形分析、意义阐释、历时演变）的视觉-语言问答任务，为计算训诂学提供了标准化框架。
2. **构建JieZi-Dataset**：开发了“专家在环”的数据构建流水线，利用权威字典《汉字源流字典》作为源文本，通过模板约束的LLM生成与分阶段人工核查，产出了超50万对高质量、多字期、多维度标注的VQA数据。
3. **构建JieZi-Bench**：从零散权威辞书（《康熙字典》《说文解字》等）中独立筛选并经由专家逐条核验，构建了约8千对高可靠性评估基准，严格与训练数据隔离以避免泄露。
4. **建立全面基线与发现模型瓶颈**：在多款前沿MLLM上进行了系统评测，揭示出现有模型在基础识别上尚可，但在字形分解、语义推理、历时演变等深层训诂任务上表现显著薄弱，并通过微调实验证实了领域特定数据的关键价值。

## 方法详解
- **任务定义**：ACCE任务接收一个古汉字图像和一个问题，生成自然语言答案。问题空间Q涵盖四个递进层次：L1基础信息（字符识别CHAR、字期分类SCRC）、L2字形分析（结构分类STRC、构件识别COMR、构件功能COMF、构件解释COMI、造字法分类FORC）、L3字义阐释（原始意义ORIM）、L4历时演变（构件演变COME、演变阐释EVOI）。
- **数据构建流水线（三阶段）**：
  1. **收集**：从《汉字源流字典》高分辨率扫描版进行OCR提取与字形定位/分类（使用YOLOv11），并结合外部数据集（ACCP、MegaHan97K）扩充多样性。对OCR结果进行全量人工校对。JieZi-Bench则从四部权威辞书交叉编译，并应用元长度阈值筛选与专家核验。
  2. **结构化**：使用Gemini-3-Flash基于提示词将字典原文解析为符合ACCE四层结构的JSON元数据记录。JieZi-Dataset抽检10%记录，JieZi-Bench全部记录均经专家核验。
  3. **VQA生成**：设计针对L1-L4的专家问答模板，结合结构化元数据作为动态上下文，约束LLM（Gemini系列）生成QA对。模板注入确保答案源自源文本，避免幻觉；问题措辞多样化；JieZi-Dataset随机抽样5千对检验，JieZi-Bench全部QA对经人工检查修订。
- **质量控制**：采用“专家在环”策略，在收集的校对、结构化的抽检/全检、VQA生成的抽检/全检各阶段嵌入人工核验，平衡规模与质量（Dataset侧重规模与阶段抽查，Bench侧重全流程全量核验）。

## 实验与结果
- **数据集规模**：JieZi-Dataset包含约1.3万个唯一字符、13万张字形图像（覆盖甲骨文、金文、战国、小篆、隶书、楷书六字期）、超50万专家审核QA对。JieZi-Bench包含1,024张字形图像和约8千QA对。
- **评估基线**：评测了包括GPT-5.4、Gemini 3.1 Pro、Claude Opus 4.6、Doubao-Seed-2.0-pro、Kimi-K2.5、GLM-4.6V、Qwen3.5系列（2B/4B/9B/35B/397B）及InternVL3.5等在内的多个商业与开源MLLM。
- **主要结果与结论**：
  - **通用模型表现**：多数模型在分类任务（如SCRC 40–77%）上中等，但在细粒度分析（如CHAR 10–37%）和深层任务（L4最高分低于40%）上表现较差，显示预训练知识不足以支撑系统训诂。
  - **中文数据优势**：拥有丰富中文/古籍语料的Doubao-Seed-2.0-pro和Kimi-K2.5在几乎所有子任务上领先，而同等规模GPT-5.4表现落后，表明**领域相关数据覆盖比模型规模更重要**。
  - **微调提升显著**：在JieZi-Dataset上微调Qwen3.5-2B/4B/9B后，所有子任务性能大幅提升。其中**9B微调模型在几乎所有指标上达到SOTA**（如CHAR 52.6，SCRC 80.1，COMR 48.1，EVOI-FAC 32.5，SCE 40.6）。**模型规模越大，深层推理任务提升越明显**（如COME从2B到9B提升12.2分）。
  - **泛化能力**：微调模型在未见字符/字形子集上，虽然字符识别（CHAR）大幅下降，但结构解析（COMF、FORC等）保持相对稳定，证明了**知识迁移而非过拟合**。
  - **字期难度**：从楷书→小篆→金文，性能逐渐下降，早期字体因视觉变异大、结构抽象而更具挑战性。
  - **消融与验证**：数据构建各阶段（结构化、VQA生成、开源数据增强）互补贡献；500K全量数据比子集（25%/50%/75%）带来持续性能提升；模型对 paraphrase 问题具有稳健性；**SFT相较于few-shot ICL、RAG、字典上下文提示等免训练策略优势显著**，证明性能增益来自模型学会了领域推理模式而非单纯的知识暴露。

## 相关工作脉络
1. **古汉字数据集**：如ACCID、ACCP、OBIMD、OracleSage、PD-OBS等，大多局限于单一脚本类型（尤其是甲骨文），标注多为稀疏符号标签或仅具基础识别/检索支持，缺乏多维度自然语言解释。本文覆盖多字期、十项细分任务，填补全面训诂数据空白。
2. **古文字评测基准**：如OBI-Bench、Oracle-Bench聚焦甲骨文考古场景，C³-Bench、MCS-Bench、AC-EVAL面向古典文献层面，均非针对单字多维度视觉-语言综合分析。JieZi-Bench首次提供系统评估ACCE四层任务的基准。
3. **多模态大模型古文字应用**：如tonggu-vl专注于古籍文本识别与阅读，在ACCE深层训诂任务上几乎无效（多数子任务得分低于5%），证明训诂与识别是本质不同的任务，需要专门的训练与数据。
4. **汉字字形分析与组件研究**：如OBI Component 20、EvOBC等提供组件级标注，但同样限于特定脚本且无系统性的问答训练资源。本文将组件分析纳入统一VQA框架并大规模生成训练数据。

## 局限性与未来方向
- **数据来源偏向**：训练数据主要来源于《汉字源流字典》等现代权威辞书，其学术观点可能代表某一学派立场，未能充分涵盖学术争议。
- **早期脚本挑战仍大**：金文、甲骨文等早期字体的识别与分析性能远低于晚近字体，视觉变异与学术解读分歧是主要障碍。
- **任务覆盖广度**：虽涵盖十项子任务，但训诂学中还包括字形比对、异体字关系、出土文献用字等特殊场景尚未充分建模。
- **未来方向**：可扩展至其他古文字系统（如西夏文、彝文）；引入更多模态（如拓片、简牍影像）；探索自监督/弱监督学习以降低标注依赖；结合大模型智能体进行交互式、假设驱动的自动训诂探索。

## 研究启发与可借鉴点
1. **“专家在环”的数据构建流水线**：将专家知识融入数据流水线的关键节点（模板设计、源文本约束、分阶段核查），可在高成本高专业门槛领域（如法医学、专业历史研究）大规模生成可信训练数据，兼具可扩展性与质量保障。
2. **递进层次任务形式化**：将复杂专业分析过程分解为多个认知层次（识别→结构→语义→演化），并设计对应的问答模板，为其他复杂分析任务（如科学论文解读、法律案例推理）的模型训练提供了任务建模参考。
3. **评估指标的组合与验证**：针对不同类型输出（分类、序列、开放生成、复杂论述）分别采用Accuracy、F1-Score、BERTScore、LLM-as-a-Judge，并对自动指标（BERTScore、LLM-Judge）进行与人类专家的相关性验证，确保了评测的严谨性与可比性。
4. **免训练策略与微调的对比实验设计**：通过设置Few-shot ICL、RAG、Prompting等基线，明确区分了“知识暴露”与“推理模式学习”的贡献，这种实验设计对评估领域数据真实价值的通用方法具有借鉴意义。
5. **细粒度泛化能力分析**：不仅报告整体指标，还深入分析模型在未见字符、未见字形、不同字期、不同组件等子集上的性能衰减模式，揭示了模型真实学到的能力边界，为后续研究提供了详细的诊断依据。

## 关键术语表
- **ACCE (Ancient Chinese Character Exegesis)**：古代汉字训诂，指结合字形、字义、历时演变对单个古汉字进行系统学术分析的过程。
- **JieZi-Dataset**：本文构建的大规模训练数据集，包含约50万专家审核的VQA对，覆盖六字期、十项ACCE子任务。
- **JieZi-Bench**：本文构建的评估基准，包含1,024张字形图像和约8千QA对，全部由专家逐条核验，严格隔离于训练数据。
- **L1-L4 递进层次**：ACCE任务的四个分析层级：L1基础信息（识别与字期）、L2字形分析（结构、构件、造字法）、L3字义阐释（原始意义）、L4历时演变（构件演变与整体演变解释）。
- **专家在环（Expert-in-the-Loop）**：在数据构建的各个阶段（收集、结构化、生成）嵌入人工审核与干预，以确保数据的事实准确性与领域专业性。
- **模板约束生成**：利用领域专家设计的问答模板，将LLM的生成限制在源文本证据的范围内，有效抑制幻觉并保证格式一致性。
- **LLM-as-a-Judge**：使用另一个大型语言模型作为裁判，对开放式回答的事实吻合度（Fact Alignment）和学术表达（Scholarly Expression）进行自动评估。
- **多字期（Script Stage）**：指汉字在不同历史时期的字形阶段，本文为甲骨文、金文、战国文字、小篆、隶书、楷书六种。

## 可复现要素
- **数据集**：JieZi-Dataset与JieZi-Bench均在GitHub公开（https://github.com/Ran00w/JieZi）。
- **代码**：模型训练与评测代码已开源。
- **关键超参**：训练使用8张Ascend 910B NPU；对不同规模模型（2B/4B/9B）采用固定学习率1e-5、cosine schedule、warmup ratio 0.05、weight decay 0.1、AdamW优化器；最大序列长度2048（9B模型为1024）；batch size 64-128；精度bf16；训练5个epoch。
