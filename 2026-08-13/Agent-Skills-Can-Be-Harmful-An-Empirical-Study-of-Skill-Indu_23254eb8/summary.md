# 论文速读：Agent-Skills-Can-Be-Harmful-An-Empirical-Study-of-Skill-Indu

## 一句话总结
本文针对 LLM Agent 中"技能（Skill）"复用可能引发的功能性失败与效率退化问题，构建了基于差分对比的故障归因数据集（共 307 例确认故障），并提出了自动化归因工具 SKILLTRIAGE，首次系统揭示了技能导致 Agent 失效的根因机制。

## 研究问题与动机
1. **核心问题**：Agent Skill 作为可复用的过程性知识包，在提升任务成功率的同时，也可能引发功能性失败（任务未通过验证）或效率退化（通过但 token/耗时显著增加），且现有基准缺乏对故障机制的深度归因能力。
2. **现有评估的不足**：
   - 现有技能基准（如 SkillsBench、SWE-Skills-Bench）主要衡量技能效用（通过率、成本），而非挖掘故障机制，缺乏负例与对比参照。
   - 单纯对比"有技能 vs 无技能"无法区分技能导致的失败与模型能力、环境噪声或验证器范围限制。
   - 人工归因无法扩展到技能市场持续筛查新技能的需求，缺乏可自动化的故障分类与证据提取方法。
   - 已有长上下文、无关上下文研究仅解释宏观影响，无法定位具体技能文档如何导致验证器面前的功能性失败或隐性效率退化。

## 核心贡献（创新点）
1. **构建了首个技能诱导 Agent 故障差分对比数据集**：基于 SkillsBench 与 SWE-Skills-Bench，通过语义匹配扩展公共技能，得到 307 例确认故障（125 例功能性失败、182 例高效率退化），每例均经无技能或语义匹配技能参照运行验证。与仅报告通过率/成本的现有工作不同，本文聚焦于故障机制的归因分析。
2. **首次系统分类技能诱导的功能性失败与效率退化的根因**：提出功能故障四分类（APM、EM、TIF、AM）与效率退化三分类（CO、EP、DO），发现看似相关的技能常导致"任务实现错误/遗漏"（占功能故障 68.8%）以及"过度验证/重型实现流水线"（占效率退化 62.6%），而非明显的无关技能问题。
3. **开发了 SKILLTRIAGE 自动化归因工具**：将手动分类taxonomy操作化为差分证据提取与归因流程，基于 GPT-5.5 在三组独立运行中通过 2-of-3 投票实现功能故障子类别 88.8% 准确率、效率退化子类别 72.5% 准确率，为技能平台提供可缩放的故障诊断支持。

## 方法详解
1. **差分测试框架（Differential Testing Framework）**：
   - 构建配对执行：固定任务、验证器、Agent 框架、模型、仓库/容器状态与输入数据，仅改变技能设置（无技能 vs. 目标技能，或目标技能 vs. 语义匹配技能）。
   - 定义两类故障：
     - **功能性失败（Functional Failure）**：目标运行 FAIL，参考运行 PASS。
     - **效率退化（Efficiency Regression）**：目标与参考运行均 PASS，但目标运行的 token 使用量与执行时间至少有一项超过阈值 T（默认 T=2.0），且两者均增加。
2. **数据集构建**：
   - 基准：SkillsBench（84 任务）与 SWE-Skills-Bench（490 任务）。
   - 技能扩展：从 smithery.ai 与 skillsmp.com 检索与基准技能语义相似（余弦相似度≥0.7，使用 all-MiniLM-L6-v2 嵌入）的公共技能，每个任务最多扩展至 6 种技能变体。
   - 潜在配对比较从 826 扩充至 20,664 组（约 25 倍扩展）。
   - 使用 OpenCode 1.15.1 与 Claude Opus 4.6 执行，记录轨迹、验证器结果、token 用量与执行时间。
3. **故障标签与细化**：
   - 自动识别候选故障（665 例），通过排除证据不足、验证器误报、重复案例后得到 307 例确认故障。
   - 人工审查并分配单一根因标签，最终通过小组共识确定。
4. **SKILLTRIAGE 工具设计**：
   - **输入标准化**：将配对案例统一为任务视图、目标运行视图、参考运行视图。
   - **差分证据提取**：
     - 功能故障：计算五个差分信号（DS1–DS5），分别检验环境/运行时变化、技能显式或间接诱导、任务指定路径 vs. 实际写入路径、必需元素是否生成、实现错误 vs. 遗漏。
     - 效率退化：按阶段（探索、实现、验证/调试）与动作标签（探索、流水线、验证、依赖修复、参考加载）计算 token/时间成本增量。
   - **归因**：将 taxonomy 定义、标准化输入、差分证据输入 LLM，选择最能同时解释目标结果与轨迹分歧的根因标签，输出类别、子类别、自然语言理由、证据引用与修复建议。

## 实验与结果
- **数据集**：SkillsBench（11 领域，84 任务）、SWE-Skills-Bench（490 软件工程专业任务）。
- **评估基线**：无技能运行、基准内置技能、语义匹配公共技能。
- **主要结果数字**：
  - 最终分析数据集：**307 例**确认故障（125 功能性失败 + 182 高效率退化，阈值 T=2.0）。
  - **功能性失败根因分布**：任务实现故障（TIF）占 86/125（**68.8%**），其中错误填写必需元素（IRF）46 例（36.8%）、必需元素遗漏（RRO）36 例（28.8%）；环境不匹配（EM）13 例（10.4%）；工件误放置（AM）24 例（19.2%）；适用性不匹配（APM）仅 2 例（1.6%）。
  - **效率退化根因分布**：过度流程（EP）占 114/182（**62.6%**），其中过度验证（EV）67 例（36.8%）、重型实现流水线（HIP）30 例（16.5%）；上下文膨胀（CO）46 例（25.3%），几乎全部来自技能主体文本（SBCB 43 例）；依赖解析（DO）22 例（12.1%）。
  - **SKILLTRIAGE 归因性能**：
    - 功能故障：类别准确率 93.6%（117/125），子类别准确率 **88.8%**（111/125）；在最大的 TIF 子集中子类别准确率 88.4%（76/86）。
    - 效率退化：类别准确率 79.7%（145/182），子类别准确率 **72.5%**（132/182）；在 EP 子集中子类别准确率 68.4%（78/114）。
- **最强结果与提升**：SKILLTRIAGE 在功能故障子类别归因上达到 88.8% 准确率，显著高于仅依赖原始轨迹的基线；功能故障主要根因"任务实现错误/遗漏"占比近七成，这一发现挑战了"技能失效多因明显无关"的直觉。

## 相关工作脉络
1. **Agent Skills 与技能基准**：与 SkillsBench、SWE-Skills-Bench 相比，本文不局限于度量技能效用（通过率提升），而是聚焦于技能诱导的负向效果与机制归因。
2. **上下文工程与长上下文研究**：Prior work（Lost in the middle、distracted by irrelevant context 等）证明额外上下文非线性有益；本文进一步揭示特定技能内容如何通过改变执行轨迹（而非仅增加 prompt 长度）导致效率退化与功能故障。
3. **Empirical Agent 故障分析**：与 MAST、Agentless、SWE-agent 等从轨迹分析 Agent 失败的工作相比，本文的归因单元是"加载的技能"，在控制模型、验证器、环境的条件下进行差分对比，隔离技能特有的影响。
4. **软件工程中性能/配置 Bug 研究**：借鉴性能 bug、ML bug、配置错误 taxonomy 的思路，但将分析对象转换为"技能引导的 Agent 轨迹"，提出适用于技能复用场景的新分类体系。
5. **差分测试（Differential Testing）**：受经典差分测试启发，将其应用于 Agent 技能对比，通过配对执行（无技能 vs. 有技能、跨技能对比）构建伪 oracle，实现故障的可信归因。

## 局限性与未来方向
- **局限性**：
  1. 手动归因存在主观性，尽管通过排除模糊案例与小组共识缓解，但复杂轨迹中判断验证器范围、成本波动是否属于正常方差仍具挑战。
  2. 外部效度受限：研究基于 SkillsBench 与 SWE-Skills-Bench，使用 OpenCode 与 Claude Opus 4.6，结论可能受任务分布、Agent 框架、模型能力、技能生态影响，未必直接适用于所有设置。
  3. SKILLTRIAGE 在边界案例上仍有误差（如 IRF/RRO 混淆、多成本表面难以区分），自动化归因尚未达到完全准确。
- **未来方向**（论文自述）：
  1. **技能 - 任务兼容性检查**：在执行前后比较任务需求与候选技能内容，提取必需字段、API、路径、输出格式、域规则、环境约束，警告冲突默认值、示例、模板、路径或包状态假设。
  2. **成本感知技能打包与选择**：估算边际上下文成本，将示例/清单移至懒加载引用，预测额外探索、实现、验证、依赖修复工作量后再选择技能。
  3. **预算感知执行策略**：根据任务不确定性、仓库规模、变更风险、剩余 token/时间预算，动态调整验证范围与实现流水线深度，防止可选指导变为强制工作。

## 研究启发与可借鉴点
1. **差分对比范式可迁移**：本文的"固定一切变量，仅改变技能设置"的配对执行设计，可有效隔离技能特有因素，适用于任何 Agent 模块（提示词、工具、策略）的影响归因研究。
2. **双维度故障分析（功能 + 效率）值得借鉴**：不仅关注任务是否成功，还量化 token/耗时代价，揭示了"通过但成本暴增"的隐性退化，这对设计经济型 Agent 系统具有直接参考价值。
3. **Taxonomy-driven 自动化归因框架**：SKILLTRIAGE 将人工分类体系转化为可计算的差分信号（路径差异、阶段成本、动作标签），为构建其他领域的可解释故障诊断工具提供了方法模板。
4. **技能内容的结构化分解启示**：论文揭示"技能主体文本"是上下文膨胀的主因、"验证清单"和"实现流水线"是效率退化的核心，提醒后续技能设计应严格区分"必填需求"与"可选示例/模板"，并采用懒加载策略。
5. **与团队方向的结合机会**：若团队从事 Agent 工具调用优化、技能市场构建或效率型 Agent 研究，可直接复用本数据集、分类体系与 SKILLTRIAGE 代码，进一步探索实时兼容性检查、动态预算分配、或针对特定领域（如软件工程、科学计算）的技能失效防御机制。

## 关键术语表
- **Agent Skills**：封装任务特定过程知识的结构化包（如 SKILL.md 文件），在推理时加载到 Agent 上下文中，引导规划、工具使用、代码编辑、验证等，无需修改模型参数。
- **Differential Testing（差分测试）**：通过对比同一任务在不同技能设置下的执行结果（有/无技能、跨技能），隔离特定技能引起的故障或成本变化。
- **SKILLTRIAGE**：本文开发的基于 LLM 的自动化归因工具，将技能故障 taxonomy 操作化为差分证据提取流程，为已确认的故障生成根因分类与修复建议。
- **Task-Implementation Fault（TIF）**：技能导致 Agent 错误实现或遗漏任务必需的元素（字段、API、计算、格式、域规则），占功能故障的 68.8%，是最大根因类别。
- **Excessive Procedure（EP）**：技能将可选活动变为强制步骤，导致过度探索、重型实现流水线或过度验证，占效率退化的 62.6%，是最大成本来源。
- **Context Bloat（CO）**：技能主体文本或辅助材料持续占据 Agent 上下文，使每次模型调用成本显著增加，占效率退化的 25.3%。
- **Pass/Fail 与 PASS/PASS 配对**：功能故障定义为目标 FAIL/参考 PASS；效率退化定义为双方均 PASS 但目标成本显著更高。
- **Semantic Matching（语义匹配）**：使用 all-MiniLM-L6-v2 嵌入与余弦相似度≥0.7 阈值，从公共技能库检索与基准技能语义相近的替代技能，扩展对比空间。

## 可复现要素
- **数据集**：SkillsBench（84 任务）与 SWE-Skills-Bench（490 任务）；扩展所用的公共技能来自 smithery.ai 与 skillsmp.com。**论文未明确声明数据集是否开源**，但基准本身通常公开。
- **代码/权重**：论文未明确提及 SKILLTRIAGE 代码或模型权重是否开源。
- **关键超参**：
  - 效率退化阈值 **T = 2.0**（token 与时间比率至少一项超过 2.0，且另一项>1.0）。
  - 语义匹配相似度阈值 **余弦相似度 ≥ 0.7**，每任务最多保留 **top-5** 候选技能。
  - 嵌入模型：**all-MiniLM-L6-v2**。
  - 执行环境：**OpenCode 1.15.1** + **Claude Opus 4.6**。
  - SKILLTRIAGE 归因运行：**GPT-5.5**，每组案例独立运行 **3 次**，采用 **2-of-3 majority vote**。
