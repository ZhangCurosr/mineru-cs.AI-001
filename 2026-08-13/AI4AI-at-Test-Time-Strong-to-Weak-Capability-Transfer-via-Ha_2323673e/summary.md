# 论文速读：AI4AI at Test-Time: Strong-to-Weak Capability Transfer via Harnesses

## 一句话总结
本文提出并研究了"强-弱脚手架"（strong-to-weak scaffolding）范式：一个强构建器模型（builder）在仅使用5%验证数据的情况下，迭代构建推理时的外部脚手架（harness），帮助固定参数的弱目标模型完成Theory-of-Mind任务。实验表明该方法可将GPT-5.4-mini的平均准确率从0.488提升至0.912，增幅达87%，且提升主要来源于将不稳定推理卸载为确定性代码、基准感知路由和严格格式控制。

## 研究问题与动机
1. **核心问题**：当小模型在某任务上失败时，原因可能是内部能力不足，也可能是任务呈现方式带来的过高认知负荷。现有蒸馏方法聚焦于第一种途径（更新模型参数），本文研究第二种途径——在推理时通过外部脚手架改善任务执行环境。
2. **现有方法不足**：传统知识蒸馏、on-policy蒸馏、指令微调等均需更新弱模型参数；即便如Self-Refine等方法通过推理时结构调整，也仅优化单一模型自身的推理过程，不涉及跨模型能力转移。
3. **部署现实需求**：现代小模型部署中极少孤立使用，而是嵌入在解析输入、选择工具、检查结果、分解任务的管道中；但缺乏对脚手架为何有效、何时稳定、哪些设计选择关键的系统性分析。
4. **评估新视角**：将问题从"模型能多好地解决问题"转变为"强模型能否构建让弱模型更好解决问题的条件"，为builder模型能力评估提供新框架。

## 核心贡献（创新点）
1. **形式化强-弱脚手架为独立的推理时能力转移范式**：不同于任何参数更新方式，构建器仅在推理时设计外部结构，目标模型权重完全冻结。
2. **系统性多维度实证分析**：首次对脚手架的效果量、稳定性、验证效率、平台/目标依赖性、因果机制、认知负荷减少等进行全面量化分析（72次独立运行）。
3. **识别可操作的脚手架设计原则**：有效脚手架依赖确定性卸载、基准感知路由、格式控制和有目的的分解，而非暴力验证搜索或更长推理链。

## 方法详解
**框架流程**：
1. **数据集划分**：从四个ToM基准（BigToM、Hi-ToM、MMToM-QA、MuMA-ToM）各抽取5%作为验证集（共195样本），剩余作为隐藏测试集（3900样本）。
2. **构建器工作空间初始化**：包含任务规则文件、目标模型调用示例、验证集。
3. **迭代优化循环**：构建器基于验证集性能反复修改脚手架（包括prompt模板、路由逻辑、确定性求解器、few-shot示例、验证通过等），每次迭代记录错误样本用于诊断。
4. **最终评估**：构建完成后，人工将脚手架入口函数应用于隐藏测试集，测量最终性能。

**核心优化目标**：
- 主目标：最大化目标模型在测试集上的宏平均准确率
- 次目标：最小化验证集调用次数（鼓励高效使用验证预算）

**脚手架技术组成**：
- 格式强制（format enforcement）
- 贪心解码（greedy decoding, temperature=0）
- 基准路由（benchmark routing）
- 强制思维链（forced CoT）
- 极性/否定逻辑（polarity logic）
- 结构化提取（structured extraction）
- 确定性求解器（deterministic solver）

## 实验与结果
**数据集**：四个Theory-of-Mind基准，共3900项测试：
- BigToM（1200项，观察/信念推理）
- Hi-ToM（1200项，递归深度0-4嵌套信念）
- MMToM-QA（600项，贝叶斯目标推理）
- MuMA-ToM（900项，多智能体信念推理）

**基线**：
- Vanilla：无脚手架直接调用，GPT-5.4-mini准确率0.488
- Human-Inspired Harness（UserHarness）：人工设计，准确率0.939

**主要结果**（以GPT-5.4-mini为目标的57次运行）：
- 平均提升：+0.275（0.488→0.763）
- 最佳结果：GPT-5.5构建器在GPT Codex上达到0.912（+0.423，相对提升86.7%）
- 所有11个构建器配置均超越vanilla基线（100%成功率）
- 最佳脚手架超越无脚手架的GPT-5.4（0.619）和GPT-OSS-120B

**关键发现**：
- 构建器能力主导效果，平台效应仅为二阶因素（native平台平均仅+0.013）
- 构建器推理努力程度与脚手架质量单调正相关（Spearman ρ = 0.77）
- 验证迭代次数与最终性能几乎无关（r = 0.17），但最佳验证准确率与最终测试准确率高度相关（r = 0.96）
- 弱目标模型（GPT-5.4-mini）获得更大增益（+0.262），强目标模型（Gemini-3.5-flash）增益较小（+0.110），且在高基线任务上可能退化
- 确定性卸载比例与最终准确率强相关（r = 0.72）

## 相关工作脉络
1. **知识蒸馏（Hinton et al., 2015; Hsieh et al., 2023）**：通过参数更新将强模型知识转移到弱模型，本文方法完全不更新目标模型参数，属于互补范式。
2. **推理时提示与分解（Wei et al., 2022; Yao et al., 2022; Madaan et al., 2023）**：如CoT、Self-Refine等方法优化单一模型的推理过程，本文研究跨模型的脚手架构建，目标模型是固定的执行者。
3. **工具使用与程序化推理（Schick et al., 2023; Gao et al., 2023）**：强调将计算卸载到外部工具，本文在此基础上系统研究了这种卸载如何在强-弱转移场景中自动涌现。
4. **脚手架工程（Khattab et al., 2023; Lee et al., 2026）**：DSPy和Meta-Harness等工作将prompt/管道作为优化目标，但未明确设定强-弱能力转移的对比场景。
5. **弱到强泛化（Burns et al., 2023）**：研究弱监督如何激发强模型能力，仍属参数更新范式；本文反向操作，研究强模型如何辅助弱模型。
6. **Theory-of-Mind基准（Gandhi et al., 2023; Wu et al., 2023）**：本文选用这些基准作为测试床，因其兼具可编译结构和难以简化的核心推理，适合分析脚手架的有效边界。

## 局限性与未来方向
1. **任务范围限制**：仅在Theory-of-Mind基准上验证，虽涵盖多种子类型但不足以代表所有推理场景；需扩展到含不同符号结构、模糊性和开放式推理的基准族。
2. **未探索参数协同**：脚手架与模型微调的互补关系未深入研究，未来可探索脚手架引导训练或训练引导脚手架设计的协同路径。
3. **潜在过拟合风险**：虽然验证-测试差距很小（平均0.021），但仅5%验证数据仍存在过度拟合隐式结构的风险。
4. **复杂推理剩余误差**：高阶递归信念追踪、欺骗场景、贝叶斯目标推理仍是瓶颈，现有脚手架无法完全处理这些最难子类型。
5. **未来方向**：①探索更广泛的任务领域；②研究脚手架自进化机制；③将本设置发展为标准化的builder模型能力基准。

## 研究启发与可借鉴点
1. **验证效率高于验证量**：构建器仅需约5次验证迭代即可收敛，且验证质量（构建器能力）远关键于验证数量；这为后续研究提供启示：应关注构建器"假设形成能力"而非单纯增加反馈轮次。
2. **确定性卸载作为核心机制**：将任务结构编译为代码/规则可直接减少目标模型认知负荷，这一机制可迁移至其他需要结构化推理的任务（如数学、代码生成）。
3. **能力匹配原则**：强目标模型上过度脚手架可能导致性能退化（打破已有正确行为），这对后续研究设计脚手架部署策略有直接启发——需根据目标模型"可用余量"动态调整干预强度。
4. **跨设计互补性**：不同强构建器发现的错误修复机制部分重叠但非完全重合，取并集可覆盖97%的基线错误；这提示可借鉴集成多种独立脚手架的思路。
5. **平台效应的条件性**：原生平台优势仅在构建器具备足够推理努力时才显现，这对构建自动化脚手架系统时的工程选择有参考价值。

## 关键术语表
**Strong-to-Weak Scaffolding**：强模型在推理时为弱模型构建外部脚手架，无需更新目标模型参数即可实现能力转移。

**Builder Model**：负责设计和迭代优化脚手架的强模型，其能力决定最终脚手架质量。

**Target Model**：被脚手架辅助执行任务的固定弱模型，其参数在整个过程中不被更新。

**Harness/Scaffold**：包围目标模型的推理时外部结构，包含路由逻辑、prompt模板、确定性求解器、验证机制等组件。

**Deterministic Offloading**：将任务中的可预测子结构编译为代码或规则执行，直接减少目标模型的认知负荷。

**Validation-Efficient**：仅需少量验证迭代即可收敛的高质量脚手架构建特性。

**Headroom Law**：脚手架增益与目标模型在特定基准上的"可用余量"（1-基线准确率）强相关的规律。

**Cognitive Load Reduction**：通过脚手架设计降低目标模型执行任务所需的推理负担。

## 可复现要素
- **数据集**：BigToM、Hi-ToM、MMToM-QA、MuMA-ToM均为公开基准，论文使用固定随机种子划分5%验证集。
- **代码/权重**：论文未提及开源代码或预训练权重。
- **关键超参**：验证集比例5%、目标模型（GPT-5.4-mini、Gemini-3.5-flash）、构建器模型（Opus-4.7多个推理层级、GPT-5.5、Gemini-3.1-Pro等）、平台（Cursor、Claude Code、GPT Codex）、重复次数3次。
