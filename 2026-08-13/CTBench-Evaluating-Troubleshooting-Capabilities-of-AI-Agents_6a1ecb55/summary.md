# 论文速读：CTBench-Evaluating-Troubleshooting-Capabilities-of-AI-Agents

## 一句话总结
本文提出了 **CTBench**，一个面向电信网络运维（NetO&M）的 AI Agent 排障能力公开评测基准，覆盖根本原因分析（RCA）与路径恢复两类任务；通过专家标注的验证步骤（golden evidence）与多维指标，系统评估 Agent 在部分可观测、多厂商异构环境下的诊断过程与最终答案质量。

## 研究问题与动机
- 现有电信基准通常假设**全可观测性**、**单一厂商拓扑**，且仅评估最终答案，无法反映真实网络中多厂商、多协议接口、部分可观测的排障条件。
- 现有基准无法区分“无法定位故障”与“给出正确答案但缺乏证据支撑”的 Agent；而在运维实践中，**诊断过程的可解释性与证据链完整性**是建立操作信任的前提。
- 真实网络存在**跨层级联故障**与**复杂故障传播链**，要求 Agent 具备多步假设-验证、跨设备角色推理与冗余证据交叉核对能力，现有通用 Agent 基准未覆盖此类专业约束。
- 当前电信领域已有若干基准（如 NIKA、NetArena、NetAgentBench 等），但它们在可观测性、异构设备支持、证据驱动评估等关键维度上存在明显缺口，CTBench 旨在填补这一空白。

## 核心贡献（创新点）
- **提出 CTBench 公开基准**：构建 234 个专家 curated 任务（126 个 RCA + 108 个路径恢复），包含权威答案与专家验证的 golden evidence 步骤，支持端到端交互式诊断评估。
- **定义多维专家级能力指标**：分别量化定位、根因识别、路径恢复、证据获取、可观测性鲁棒性、异构设备/厂商处理与资源消耗，避免单一准确率掩盖能力差异。
- **构建任务难度元数据体系**：标注证据可观测性、根因数量、故障传播链长度、协议复杂度、网络异构性、解路径长度等结构化字段，支持细粒度归因分析。
- **揭示当前 Agent 的系统性短板**：评测多个代表性 harness-model 组合，发现 Agent 在路径端点识别上较强，但在证据驱动 RCA、部分可观测推理与异构环境适应方面存在显著差距。

## 方法详解
- **任务形式化**：将排障建模为交互式决策问题，Agent $\pi_\theta$ 每轮根据任务指令 $q_\tau$ 与历史轨迹 $h_{t-1}$ 选择诊断动作 $a_t$（执行命令或查询遥测），环境返回观察 $o_t$，最终解码预测答案 $\hat{y}_\tau$。
- **两类任务**：
  - **RCA 任务**：目标答案为标准化根因三元组集合 $\{(n_i, o_i, c_i)\}$，分别表示受影响节点、对象与根因标签。
  - **路径恢复任务**：目标答案为有序转发路径元素序列 $\{p_1, p_2, \dots, p_k\}$，需保留跳序、多路径与出口接口语义。
- **专家标注流程**：15 名资深电信专家（平均 20 年经验）基于真实维护案例抽象候选任务并脱敏；独立专家盲测验证可解性与证据一致性，达成共识后保留。
- **Golden Evidence 定义**：每个任务标注关键诊断动作集合 $\mathcal{A}^*(q_\tau) = \{a_1^*, \dots, a_{T^*}^*\}$，作为评估 Agent 轨迹证据覆盖率的确定性参考。
- **评估框架**：自动比对 Agent 轨迹与黄金答案/证据，计算 RCA-Loc、RCA-ID、RCA-Evidence（F1）、Path-Loc、Path-Rest、Path-Evidence 等指标；同时报告延迟、交互轮次与 token 消耗。
- **辅助评分机制**：引入层次化 RCA 评分（按根因标签语义层级给予部分分）与拓扑感知节点相似度（结合拓扑距离与角色聚类），用于近错过误分析。

## 实验与结果
- **数据集**：126 个 RCA 任务、108 个路径恢复任务，共 234 个；根因条目 214 个，涵盖 17 种细粒度故障类型。
- **评测基线**：Codex+GPT-5.5、ClaudeCode+Qwen3.7-Plus、HermesAgent+DeepSeek-V4-Pro、HermesAgent+Qwen3.7-Max、HermesAgent+TelecomGPT-R1。
- **最强结果**：Codex+GPT-5.5 整体最优，RCA 准确率 **47.62%**，路径恢复准确率 **87.96%**；人类专家独立评测准确率为 RCA 56.4%、路径恢复 92.6%。
- **关键发现**：
  - 路径恢复**端点识别**普遍较高（最高 Path-Loc 99.38%），但**完整路径恢复**与**证据收集**较弱（Codex+GPT-5.5 的 Path-Evid. 仅 47.84%）。
  - RCA **识别率**（66.83%）显著高于**定位率**（52.90%），表明 Agent 常能推断故障类型但难以精确到具体节点/对象。
  - 即使答案正确，**证据覆盖率**仍有限（Codex+GPT-5.5 在恰好答对任务中证据覆盖率约 58%），说明“答对”不等于“证据驱动诊断”。
  - **更高计算成本不必然带来更强诊断能力**：ClaudeCode+Qwen3.7-Plus 消耗更多轮次与 token，但整体表现低于 Codex+GPT-5.5。
  - **故障类别差异显著**：C2（安全/NAT/访问控制）最易诊断，C1（接口/链路状态）最难（准确率 0–10.71%），C3（路由/策略控制）除 Codex+GPT-5.5（40%）外其他 Agent 完全无法解决。
  - **部分可观测性与异构性**：在 O2（部分可观测）条件下，ClaudeCode+Qwen3.7-Plus 的 RCA 准确率从 20.56% 降至 15.79%；路径恢复在高异构场景下准确率从 29.31% 骤降至 4.00%。

## 相关工作脉络
- **NIKA、NetArena、NetAgentBench**：现有电信排障基准，但均假设全可观测、单一域拓扑，且仅评估最终答案，缺乏证据驱动与异构设备支持。
- **TeleQnA、ORAN-Bench**：知识型基准，仅评估模型对电信标准/协议的理解，不涉及交互式诊断轨迹与工具调用能力。
- **SWE-bench、AgentBench、GAIA**：通用 Agent 基准，关注多步推理与工具使用，但未覆盖厂商特定命令语法、拓扑推理、跨层故障传播等专业约束。
- **WirelessAgent++、TelcoAgentBench**：面向无线网络的 Agent 基准，但仍缺乏对多厂商核心网设备、部分可观测性与专家验证证据的全面支持。
- **CTBench 的定位差异**：首次同时强调专家验证轨迹、部分可观测性、异构环境适应与多维度证据指标，填补真实电信 NetO&M 场景评估空白。

## 局限性与未来方向
- 当前仅覆盖 **RCA 与路径恢复** 两类任务，未包含动态修复故障的闭环操作评估。
- 尚未全面覆盖**无线接入网、核心网切片、云原生电信基础设施**等所有电信子域。
- 任务集规模（234 个）相对有限，未来可扩展至更大规模与更复杂场景。
- 部分可观测性与异构性的定量分析主要基于单一代表性 Agent（ClaudeCode+Qwen3.7-Plus），其他 Agent 的详细趋势需在补充材料中进一步挖掘。

## 研究启发与可借鉴点
- **Golden Evidence 与轨迹级评估**：不仅评估最终答案，还量化 Agent 收集的诊断证据与专家步骤的重合度，这一思路可迁移至医疗诊断、工业控制等其他专业领域的 Agent 评测。
- **层次化评分与拓扑感知相似度**：通过语义层级与拓扑距离提供近错过误分析，有助于更细致地理解模型失败模式，值得在其他基准中借鉴以避免严格匹配带来的评估失真。
- **任务难度元数据体系**：将可观测性、异构性、协议复杂度、传播链长度等结构化标注，支持细粒度能力分析，为后续研究提供可复用的任务特征分析方法。
- **Harness-Model 组合评测范式**：指出评估应聚焦 harness-model 整体而非孤立模型，因为不同 harness 在工具调度、状态序列化、停止行为上差异显著，这一方法论对 Agent 系统评测具有重要参考价值。

## 关键术语表
- **CTBench**：面向电信网络运维的 AI Agent 排障能力公共评测基准，包含 RCA 与路径恢复两类任务及专家标注证据。
- **RCA（Root Cause Analysis）**：根本原因分析，指 Agent 定位网络故障节点、对象及根因标签的诊断过程。
- **Golden Evidence**：专家验证的关键诊断动作集合，作为评估 Agent 轨迹证据质量的参考标准。
- **Evidence Observability**：证据可观测性，分为 O1（直接命令可获得决定性证据）与 O2（需通过间接命令推断）两级。
- **Network Heterogeneity**：网络异构性，指任务涉及的不同厂商数量与设备类型数量，影响 Agent 跨环境适应能力。
- **Fault-Propagation Chain**：故障传播链，描述潜在根因到中间网络状态再到观察症状的因果路径长度。
- **Hierarchical RCA Scoring**：层次化 RCA 评分，通过根因标签语义层级给予部分分数，用于近错过误分析。
- **Path Restoration**：路径恢复，指 Agent 重建服务转发路径的任务，要求输出有序节点-接口序列。

## 可复现要素
- **数据集**：CTBench 为公开基准，任务示例、元数据分布与标注协议见论文补充材料。
- **代码/权重**：评测代码与环境细节见补充材料 D 节，包含 prompt 模板、命令格式与运行脚本；模型通过厂商 API 调用（GPT-5.5、Qwen3.7-Plus、DeepSeek-V4-Pro、Qwen3.7-Max、TelecomGPT-R1），权重未开源。
- **关键超参**：并发数=3，最大运行时间=3600 秒/任务，harness 版本固定（Codex v0.141.0、ClaudeCode v2.1.63、HermesAgent v0.16.0）。
