# 论文速读：NetlistBench: Evaluating LLM Reliability in SPICE Netlist Recognition and Manipulation

## 一句话总结
论文提出了 NetlistBench，一个面向 SPICE 网表的**结构验证基准测试**，将网表可靠性确立为独立于高层设计推理的表征层评估问题；实验表明当前 LLM 在简单局部操作（删除/参数修改）上可靠（96%–100%），但在连通性敏感操作、层级处理和长程复合编辑（15 步后降至 0%–34%）上仍存在结构性失败。

## 研究问题与动机
- **LLM 在 EDA 工作流中的可靠性未被量化**：LLM 已广泛应用于模拟电路生成、仿真优化、网表转原理图等流程，但面向仿真器的 SPICE 网表识别与修改的可靠性缺乏系统评估。
- **现有代码基准无法捕获电路语义**：SWE-bench 等通用代码基准以单元测试评估功能正确性，无法刻画 SPICE 的设备终端语义、共享节点连接和有序子电路接口。
- **现有电路基准未分离表示层操作**：CIRCUIT、AMSbench 等聚焦端到端结果（仿真成功、规格提升），未将"解释/修改网表"这一基础操作从高层推理中剥离出来单独评估。
- **网表错误会直接传播到下游**：网表层故障会导致仿真/布局/优化连锁错误，可靠网表操作是实现可信 LLM-EDA 的前提条件。

## 核心贡献（创新点）
1. **将 SPICE 网表可靠性形式化为表征层评估问题**：区别于以往端到端任务完成度评估，本文聚焦"LLM 能否正确识别与操作网表作为结构化电路对象"这一前提性问题。
2. **构建 NetlistBench 结构验证基准**：涵盖 24 个任务族、2,342 个案例（识别 800 例 + 编辑 1,542 例），支持确定性格线化的 ground truth 和可复现评估。
3. **开发结构感知评估流程（Structure-Aware Oracle）**：基于标准化电路表示（Canonical IR）进行精确结构比对，超越字符串相似度或最终仿真验证。
4. **揭示操作类型与编辑距离对可靠性的分层影响**：发现局部操作高可靠、长程复合编辑呈指数衰减、推理增强可缓解但无法消除结构性失败。

## 方法详解
- **基准构建流程**：从 AnalogGenie（扁平 CMOS 模拟网表）和 ALIGN（层次化网表，21 种拓扑族）两个源库出发，通过**确定性模板流水线**实例化评估案例，每个实例为三元组 $(N_{\text{src}}, T_{\text{inst}}, Y_{\text{target}})$，包含源网表、明确任务指令和任务特定的评估目标。
- **结构感知 Oracle 原理**：将模型输出与参考目标统一解析为**规范电路表示（Canonical IR）**——列出每个器件的实例名、器件类型、有序终端节点、参数、顶层指令及子电路端口接口；比较规则包括：同名设备集一致、无多余或缺失器件、终端-节点绑定一致、参数数值归一化后相等（如 `1k = 1000`）、对称两终端无源器件（R/L/C） terminals 无序比较、子电路定义端口顺序视为语义。
- **等价判定任务标签验证**：对 equivalence judgment 子集，将 IR 投影为**带标签的二分器件-网络图**（器件节点标类型/模型/归一化参数签名，边标终端角色），使用 VF2 图同构算法验证正负样本标签的正确性（注意：VF2 仅用于标签审计，不作为评分手段）。
- **原子操作类型分类**：识别类（8 族：器件参数提取、终端连通性、节点关联、子电路端口映射、结构等价判定等）；编辑类（16 族：连通性编辑、器件增/删/替换、参数编辑、重命名传播、3/6/9/12/15 步复合编辑、子电路展开、端口交换、层级复合编辑）。

## 实验与结果
- **数据集规模**：2,342 个案例（Flat 来源 2,838 条归一化后选取，ALIGN 层级来源 931 条）；覆盖 24 任务族。
- **评估模型**：Claude Sonnet 4.6、GPT-4.1、Gemini 2.5 Flash、DeepSeek-V4-Flash、Qwen3.6-Flash、Qwen3-30B-A3B（均禁用 thinking 模式）；另单独评估 DeepSeek-V4-Flash 启用原生思考模式。
- **最强基线**：Claude Sonnet 4.6 总体通过率 **82%**（非思维模型中最高）；启用推理后 DeepSeek-V4-Flash 达到 **81%**（接近 Claude，但部分类别仍落后）。
- **操作类型分层结果**：
  - 简单局部操作：**Device remove = 97%–100%**，**Param edit = 96%–100%**，模型间差异小。
  - 连通性敏感操作：Connectivity edit 59%–97%，Device add 41%–83%，Device replace 61%–95%。
  - 结构等价判定：Equiv. judge 49%–90%。
  - 层级操作：Subckt inline 展开 2%–62%，Port swap 19%–88%。
- **长程复合编辑衰减**：3 步编辑时 Claude 80%、GPT-4.1 71%；**15 步时 Claude 跌至 26%、GPT-4.1 跌至 34%、其他模型接近 0%**。推理模式 DeepSeek-V4-Flash+R 在 3 步达 74%、15 步仍降至 31%，趋势持续。
- **缓解策略**：推理模式（Native thinking）带来最大增益（DeepSeek 52%→81%，Qwen 45%→85%，p<10⁻⁶）；PySpice 结构化表示对 DeepSeek 有小幅提升（52%→58%，p<0.001），但对 Qwen 无显著效果（45%→45%，p=0.51）。

## 相关工作脉络
- **CIRCUIT / AMSbench**：前者评估电路解释与多步推理能力，后者评估 MLLM 在 AMS 领域的综合能力，均未隔离网表表示层的基础操作。
- **SPICEPilot / SPICEAssistant / AnalogCoder / Spice Wizard**：依赖仿真反馈、语法检查或工具辅助修复循环来提升生成质量，侧面印证未经验证的 LLM 输出在网表生成上可靠性不足。
- **SPICED**：聚焦于 A/MS 网表中的语法 Bug 和模拟 Trojan 检测，研究重点为错误定位而非结构化操作可靠性。
- **CircuitFormer**：指出标准语言 tokenization 与电路图语义之间的不匹配，但未提供系统性的网表操作基准。
- **Image2Net**：使用图结构网表比较而非字符串匹配评估原理图到网表的转换，本文的结构感知评估思路与其一致。
- **SWE-bench / CodeLlama 代码基准**：以单元测试评估代码功能正确性，不适用于 SPICE 网表特有的拓扑/终端语义验证。

## 局限性与未来方向
- **规模与域局限**：仅覆盖数千器件级的模拟 CMOS 模块，未涉及工业级 post-layout 网表（百万级器件/寄生）、RF/功率/数字混合信号网表。
- **语法覆盖不全**：未充分覆盖 `.param` 符号表达式、复杂 `.model` 卡、受控源、include 层级、提取寄生参数及 PDK 特定语法。
- **指令多样性有限**：确定性模板生成的任务指令不能反映真实设计师与助手交互的语言变体和设计意图。
- **单次采样**：每个模型-案例对仅评测一次，结果反映的是 API snapshot 而非完整输出分布。
- **未来方向**：开发分解式编辑工作流、每步后结构验证、探索图结构/显式拓扑的网表表示（替代原始 SPICE 文本）。

## 研究启发与可借鉴点
- **结构感知评估范式可迁移**：基于 Canonical IR 的结构等价性比较思路可扩展到其他领域结构化文本（如 JSON/YAML 配置操作、HTML/DOM 编辑、Proto/IDL 协议操作）的 LLM 评估。
- **确定性模板驱动实例生成**：通过模板而非随机生成来构造 ground truth，确保每个案例存在唯一正确答案，这一设计可推广至任何需要精确评估的序列操作任务。
- **分解式编辑工作流**：将长程复合编辑分解为中间状态验证的原子步骤，可作为构建可靠 LLM-EDA Agent 的核心策略。
- **推理增强的差异化效果**：思考模式对结构密集任务增益显著但对所有任务并非均等，提示可根据任务类型选择性启用推理以平衡效率与可靠性。
- **PySpice 作为评估桥梁**：将网表转换为结构化 Python 表示后再由 LLM 操作，可减少 SPICE 文本解析歧义，为后续研究提供新的交互协议设计思路。

## 关键术语表
- **SPICE Netlist**：面向仿真器的电路描述文本，以位置编码方式记录器件实例、终端节点、参数和子电路层级。
- **Canonical IR（规范电路表示）**：论文定义的标准化中间表示，列出每个器件的实例名、类型、有序终端节点绑定和参数，用于结构等价性比较。
- **Structure-Aware Oracle**：基于 Canonical IR 的结构感知评估器，通过精确匹配设备集、终端绑定和参数来判断模型输出是否正确。
- **Compound Editing（复合编辑）**：将多个相互依赖的原子编辑操作合并为单一指令的评估任务，用于测试 LLM 的多步操作可靠性。
- **Terminal-Node Binding（终端-节点绑定）**：SPICE 网表中器件终端与节点名称的对应关系，体现隐式电气连接。
- **Equiv. Judge（结构等价判定）**：判断两个网表是否在保持一致命名/局部性约束下描述同一电路的任务。
- **VF2 图同构**：用于验证等价判定任务标签正确性的图同构算法，将网表投影为器件-网络二分图后进行检查。
