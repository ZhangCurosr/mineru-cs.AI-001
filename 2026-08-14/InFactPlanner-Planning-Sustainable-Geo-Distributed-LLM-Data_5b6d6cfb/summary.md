# 论文速读：InFactPlanner: Planning Sustainable Geo-Distributed LLM Data Centers

## 一句话总结
本文提出 **InFactPlanner**，一个面向 LLM 推理的轨迹驱动型决策支持框架，支持在单点与地理分布式场景下进行可持续 AI 数据中心的 What-if 假设分析，能够在基础设施部署前统一量化硬件选型、可再生能源集成、选址与路由策略对能耗、碳排、水资源、延迟与服务利用率的综合影响。

## 研究问题与动机
1. LLM 推理已从一次性训练转向持续在线服务，基础设施决策直接决定长期能耗与碳足迹，但大规模建设前的直接测量成本高昂且常不可行。
2. 现有研究多呈孤岛状态：纯能效基准测试忽略地理与能源结构差异，传统 DC 碳/水优化框架又不针对 LLM 推理负载特性建模，缺乏在同一时间粒度下联合评估多目标的规划工具。
3. 新兴 Agent 与实时交互应用要求低延迟与本地上下文感知，未来 AI 基础设施将呈现“集中超大规模 DC + 密集分布式边缘”的混合形态，运营商亟需面向混合部署的前瞻性规划能力。
4. 不同站点的电网碳强度、可再生能源潜力与冷却条件差异显著，导致“延迟最优”与“可持续性最优”的部署路径往往分叉，需系统化权衡机制。

## 核心贡献（创新点）
1. **部署级可持续性分析模型**：将工作负载轨迹、硬件-模型服务画像、PUE/WUE 设施参数、本地可再生能源发电与电网动态碳强度统一至相同时间分辨率，填补了从微观执行到宏观规划的建模空白。
2. **模块化轨迹驱动框架 InFactPlanner**：以 YAML 声明式配置驱动，支持单站/多站 What-if 分析，用户可自由替换负载均衡策略、RES 预测模型与环境核算组件，无需修改核心代码即可切换场景。
3. **生产级核算精度验证**：在 DeepSeek-R1 on DGX H100/B200 真实测量基准上复现能耗与延迟分布，中位数与 IQR 偏差均控制在 10% 以内，证明抽象层对实际决策具有可靠指导价值。
4. **揭示部署权衡规律**：通过多场景实验量化了硬件功耗-性能倒挂、可再生能源选址碳收益差异及路由权重对碳-延时效应的非线性影响，为运营商提供可操作的规划先验。

## 方法详解
InFactPlanner 采用流水线式架构，核心设计如下：
- **配置与输入**：通过 YAML 描述站点地理、PUE、WUE（onsite/offsite）、服务器组（硬件类型、部署模型、并发上限、副本数）及 RES 类型（光伏/风电）；输入轨迹支持 CSV 单条明细格式或聚合到达率格式，后者可经采样或 ServeGen 合成补充 ContextTokens/GeneratedTokens。
- **仿真引擎**：基于硬件-模型 Profile（TPS、TTFT、空闲/最大功率、并发上限）进行部署级执行建模，而非 GPU 级仿真。默认轮询负载均衡，用户可扩展延迟/利用率/碳感知路由。支持静态 TPS/TFT 与动态并发自适应模式；节点瞬时功率采样自截断对数正态分布（参数取自 P5–P95 实测区间），查询级功率按当前并发数线性摊销。
- **能耗与碳核算**：设施级功率 = 节点功率 × PUE；日能耗通过对 1 秒步长功率序列离散求和转换得到。接入 RES 后，本地发电抵消部分需求，剩余电网取电乘以时间对齐的当地电网碳强度 CI（gCO₂eq/kWh，由 ENTSO-E 与 ElectricityMaps 获取）。假设 RES 自身运营期零碳排，超额发电仅将取电归零，不结算售电收益。
- **水资源核算**：结合 onsite WUE（直接用于冷却）与 offsite WUE（关联电力生产）按公式加权计算总耗水量。
- **并行与输出**：基于 Apache Ray 实现 DC 间与服务器间并行任务调度；最终由 Report Builder 输出结构化 Pandas DataFrame，支持内置可视化或下游分析。

## 实验与结果
- **数据集与基线**：Azure LLM Inference Dataset；参考基准为 DGX H100/B200 上 DeepSeek-R1 的真实生产功耗与延迟测量 [19][20]。
- **核算验证**：InFactPlanner 复现的中位能耗误差为 7.18%（传统负载）与 8.71%（推理负载），IQR 上下界误差 4.06%–8.82%，整体偏差低于 10%，且能捕捉推理类负载的能耗跃升特征。
- **可扩展性**：单日 124 万至 992 万查询、1–8 个 DC、每站 10–80 台服务器，全场景仿真时间 <30 分钟，内存峰值 <25 GB，证明抽象级建模可支撑千万级轨迹的快速探索。
- **What-if 场景结果**：
  - **硬件-模型搭配**：DGX B200 较 H100 延迟最高降低 77%，但因空闲功耗更高使周能耗/碳排上升 35%；Llama 系列较 gpt-oss 120B 能耗高 50%。最优选择高度依赖业务优先级（延迟 vs 碳 vs 精度）。
  - **RES 选址**：希腊 (GR) 与西班牙 (ES) 光伏出力相近（电网取电量差异仅 0.3%），但由于 GR 电网碳强度更高，同等光伏装机在 GR 可额外减排 7.5%，证明 RES 价值不仅取决于出力，更取决于所替代的网格清洁度。
  - **路由策略**：纯碳感知路由较轮询减排 7%，但延迟上升 22%；平衡策略（$w_c=0.5, w_u=0.5$）仅减排 1% 却将延迟波动控制在 2% 以内；碳主导策略提供折中效果。路由权重直接决定碳-延时效应的 Pareto 位置。

## 相关工作脉络
1. **SHIELD [12]**：面向多站 DC 协同优化碳/水/能，但未建模 LLM 推理负载特性与细粒度硬件-模型服务画像，缺乏 Trace-Driven 仿真能力。
2. **DynamoLLM [1]**：在延迟 SLO 约束下优化推理集群能效，未考虑地理分布式部署、本地可再生能源集成与水资源核算。
3. **Splitwise [13] & LLMServingSim 2.0 [14]**：侧重底层执行机制（Prefill/Decode 分离、KV Cache、动态批处理），仿真粒度细但耗时长，适用于微观光谱调优而非宏观部署规划。
4. **Ozcan et al. [7]**：结合 LLM 推理与碳感知模拟评估能耗与碳排，但未提供统一的多目标权衡接口与多站 What-if 探索能力。
5. **Jegham et al. (AI 水耗基准) [8]**：提出 WUE 核算范式，本文将其与电网 CI 时序、RES 出力动态耦合，形成端到端的环境账户闭环。
6. **定位差异**：InFactPlanner 属于部署级规划工具，以硬件-模型 Profile 抽象换取跨场景快速对比能力，与执行级模拟器形成互补而非替代关系。

## 局限性与未来方向
- 抽象掉批处理动态、KV Cache 压力、显存争用及 Prefill/Decode 阶段分离，在高动态或极端并发负载下可能与生产栈存在一定偏差。
- 环境核算精度强依赖输入数据的保真度，若硬件功耗曲线、TPS/TFT 实测值、RES 气象模型或 CI 时序存在误差，将直接传导至最终决策输出。
- 未计入设备隐含碳（Embodied Carbon），且对超额 RES 发电仅做“取电归零”处理，未建模电网碳信用或售电碳收益机制。
- 未来计划接入真实运营 DC 轨迹与实测功耗数据校准模型，并扩展至云-边协同架构，研究异构边缘节点在延迟、能源、碳排与资源约束下的联合部署与路由权衡。

## 研究启发与可借鉴点
1. **硬件-模型 Profile 抽象范式**：将复杂执行状态压缩为 TPS/TTFT/功率/并发四维画像，可无缝迁移至多模态、语音、推荐系统等 AI 服务的容量规划与能效评估管线。
2. **动态碳强度与 RES 时空耦合核算**：提出的“RES 出力 → 电网残余需求 → 时间对齐 CI → 碳排放”数据管道设计，可直接复用于构建碳感知调度器或企业 Scope 2 排放追踪系统。
3. **YAML 驱动与模块化替换机制**：配置即仿真、策略与核算解耦的设计模式，便于接入数字孪生平台或云厂商自服务规划控制台，支持业务方自助探索部署空间。
4. **复合路由评分函数**：$S_i = w_c \cdot \max(0, C_i - w_r R_i) + w_u \cdot U_i$ 的多目标加权设计为后续研究提供可验证的 baseline，可直接扩展至多租户、跨云或 Greenhouse Gas Protocol 合规场景。

## 关键术语表
- **InFactPlanner**：面向 LLM 推理数据中心的轨迹驱动可持续性规划与 What-if 分析框架。
- **PUE (Power Usage Effectiveness)**：数据中心总能耗与 IT 设备能耗之比，反映制冷与供电等配套开销。
- **WUE (Water Usage Effectiveness)**：每消耗 1 kWh 电力对应的水资源消耗量（升），区分 onsite 与 offsite。
- **RES (Renewable Energy Sources)**：本地可再生能源发电系统，本文主要建模光伏 PV，支持数学解析或 ML 回归两种预测路径。
- **TTFT (Time To First Token)**：从请求发起到模型输出第一个 Token 的延迟，是用户体验的关键指标。
