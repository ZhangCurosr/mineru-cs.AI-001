# 论文速读：InFactPlanner: Planning Sustainable Geo-Distributed LLM Data Centers

## 一句话总结
论文提出了 InFactPlanner，一个基于追踪数据的可配置决策支持框架，用于在大规模部署前对 LLM 推理数据中心的可持续性进行 what-if 分析，统一评估能源、碳排放、水资源、延迟和服务质量的多维权衡。

## 研究问题与动机
1. **LLM 推理可持续性从训练向持续服务转移**：训练一次性能耗高，但推理持续运行且规模全球性，预计占 LLM 全生命周期碳排放的一半以上，成为可持续设计的关键问题。
2. **部署前缺乏统一的可扩展分析工具**：现有研究各自孤立地分析能源、碳、水或延迟，缺少在统一时间分辨率下整合硬件-模型配置、可再生能源、电网碳强度和用水参数的端到端框架。
3. **地理分布式部署的权衡评估困难**：结合可再生能源与地理分布可降低环境影响，但需同步考虑延迟、利用率、碳强度时空差异，直接物理部署验证成本高昂、缓慢甚至不可行。
4. **操作决策的复杂度日益上升**：硬件选型、模型选择、工作负载放置、冷却策略、可再生能源集成和路由策略共同决定环境足迹与服务品质，需要系统化的比较分析能力。

## 核心贡献（创新点）
1. **部署级可持续性分析模型**：将工作负载特性、硬件-模型服务配置、设施参数、可再生能源发电、电网碳强度和用水参数统一到相同时间分辨率，实现端到端的能耗-碳-水-延迟联合估算。
2. **InFactPlanner 框架实现**：基于可配置 YAML 声明式配置和追踪数据的模块化流水线，支持单站点和地理分布式的快速 what-if 分析，涵盖站址选择、硬件、模型、可再生能源和路由策略对比。
3. **硬件-模型抽象层设计**：通过可配置硬件-模型配置文件（吞吐量、首 token 延迟、功耗、并发限制）抽象底层服务行为（批处理、KV-cache、prefill/decode 分离），以可复现的一致性比较替代精确生产级预测。
4. **模块化可扩展架构**：各子系统（负载平衡、可再生能源模型、碳核算、水核算）均采用可替换接口实现，支持用户用更高保真度的模型替换局部组件而不改变整体框架。
5. **实验验证与决策案例**：复现真实系统能耗估计（误差 <10%），评估多数据中心/多服务器可扩展性（百万级查询 <30 分钟），并通过四个场景化案例展示能耗最优与延迟最优选择的分歧。

## 方法详解
1. **部署配置（YAML 驱动）**：通过 YAML 文件声明仿真窗口、输入工作负载、一个或多个数据中心配置（地理位置、PUE、WUE onsite/offsite、服务器组）。每个服务器组定义硬件类型、部署模型、最大并发数和副本数，支持异构硬件-模型组合。
2. **追踪处理**：支持两种输入格式——(a) 详细查询级追踪（CSV：TIMESTAMP, ContextTokens, GeneratedTokens）直接回放；(b) 聚合到达率追踪（CSV：TIMESTAMP, InputQueries），通过采样 Azure Inference Dataset 或使用 ServeGen 合成查询级追踪。
3. **两级负载均衡**：Inter Load Balancer 在 DC 间按轮询分配请求；Intra Load Balancer 在 DC 内按轮询分配至可用服务器实例。用户可扩展 Load Balancer 接口实现延迟感知、利用率感知或碳感知路由。
4. **执行模拟**：对每个查询记录到达时间、开始时间、完成时间、延迟和并发数。支持静态 TPS/TTFT（Eq.1: `duration = TTFT + generated_tokens / TPS`）或动态 TPS 模式（TPS 随并发变化实时更新）。
5. **功率核算**：节点瞬时功率 $P_{node}(t) = x_t(P_{max} - P_{idle}) + P_{idle}$，其中 $x_t$ 服从截断对数正态分布采样；单查询功率 $P_{query}(t) = P_{node}(t) / n(t)$（Eq.2）；设施级功率 $P_{server}(t) = P_{node}(t) \cdot PUE$。
6. **能量累积**：数据中心总能量 $E_D = \frac{1}{3600}\sum_{t=0}^{D-1} P_{server}(t)$（Eq.3，秒级离散积分转为 Wh）；单查询能量 $E_{query} = (Duration/3600) \cdot \overline{P}_{query} \cdot PUE$（Eq.4）。
7. **可再生能源建模**：RES Model 组件通过地理定位调用 Open-Meteo API 获取历史气象数据，支持解析模型（太阳能辐射缩放）和 ML 模型（PyCaret 回归器）两种方式；剩余电网需求 $P_{grid,d}(t) = \max(0, P_{DC,d}(t) - P_{RES,d}(t))$。
8. **碳排放核算**：$Emissions(t) = E_{grid}(t) \cdot CI(t)$，其中 $CI = \frac{\sum_i E_i f_i}{\sum_i E_i}$（Eq.5，加权平均），来自 ENTSO-E 和 ElectricityMaps；RES 发电视为零运营碳排放，超出需求部分仅抵消至零。
9. **水资源核算**：$\text{Water} = \frac{E_{DC}}{PUE} \cdot WUE_{onsite} + E_{DC} \cdot WUE_{offsite}$（Eq.6），区分站内冷却用水和发电过程间接用水。
10. **报告构建**：所有查询级、服务器级、DC 级的执行统计与可持续性指标汇总为 Pandas DataFrame，支持内置可视化或外部分析工具。

## 实验与结果
1. **能耗验证（Table I）**：在 DeepSeek-R1 on DGX H100 设置下，复现 [19] 参考结果：传统查询中位数能耗 0.65 vs 0.70（误差 7.18%），推理查询中位数 10.66 vs 11.68（误差 8.71%）；IQR 低/高误差均 < 9%，完整保留能耗分布特征。
2. **延迟与能耗分布验证（Fig.3）**：在 DeepSeek-R1 on DGX B200 设置下，中位数能耗偏差 1.9%，中位数延迟偏差 4.5%，IQR 高度对齐。
3. **可扩展性**：单日 Azure 追踪（1.24M–9.92M 查询），单 DC 10/20/40/80 服务器运行时间 4/7/14/28 分钟；多 DC 并行时扩展性显著优于单 DC 线性增长；内存峰值 < 25GB，可在商用服务器上运行。
4. **硬件-模型配对评估（Fig.4）**：Llama 系列比 gpt-oss 120B 多消耗最多 50% 能量和 50% 碳排放；DGX B200 较 H100 增加 35% 环境足迹但降低最高 77% 延迟；决策依赖运营商优先级（环境影响 vs 延迟 vs 精度）。
5. **RES 放置选择（Fig.7）**：希腊（GR）vs 西班牙（ES）太阳能发电量差异仅 0.3%（纬度相近），但 GR 减碳效果比 ES 好 7.5%，因 GR 电网碳强度更高——证明 RES 选址取决于被替代电网的碳强度而非仅可再生能源产出。
6. **碳感知路由（Fig.8）**：纯碳路由较轮询减碳 7% 但延迟增加 22%；平衡策略（$w_c=0.5, w_u=0.5$）减碳 1% 且延迟偏差 <2%；碳主导策略（$w_c=0.75, w_u=0.25$）减碳 3% 且平衡性更好；路由权重 $(w_r, w_c, w_u)$ 决定碳-性能权衡。

## 相关工作脉络
1. **DynamoLLM [1]**：优化 LLM 推理集群在延迟 SLO 下的能源效率，但不建模地理分布部署、可再生能源集成或水资源消耗。
2. **SHIELD [12]**：联合优化地理分布式数据中心的碳、水和能耗，但不专注于 LLM 推理场景，缺乏硬件-模型级追踪驱动模拟。
3. **Splitwise [13]**：模拟分阶段 LLM 推理（prefill/decode 分离）聚焦延迟和吞吐，属于执行级精细模拟器，不适合快速部署级 what-if 分析。
4. **LLMServingSim 2.0 [14]**：支持异构和非聚合 LLM 部署模拟，建模批处理、路由、内存管理和功耗，但执行级保真度高导致模拟时间长，不适合大规模部署探索。
5. **Ozcan et al. [7]**：结合 LLM 推理和碳感知模拟估算能耗与碳排放，但未整合水资源和地理分布部署的综合分析框架。
6. **Jegham et al. [8]**：基准测试 LLM 推理的能源、水和碳足迹，提供参考方法论但未构建可配置的部署规划工具。

## 局限性与未来方向
1. **低层服务效应抽象**：框架有意省略批处理动态、KV-cache 行为和 prefill/decode 阶段分离，在高动态工作负载下可能与生产环境存在偏差。
2. **不含嵌入式碳（embodied carbon）**：未计入硬件制造和运输的碳排放，仅核算运营阶段能耗与排放。
3. **RE 盈余不贡献外销收益**：超出需求的本地 RE 发电仅抵消至零电网需求，未建模剩余电力外销信用或储能。
4. **高精度模型依赖输入数据质量**：能耗核算准确性依赖于硬件功耗曲线、吞吐量估计、RE 模型、气象数据、电网碳强度和 WUE 参数的保真度。
5. **未来验证方向**：计划用运营 DC 真实追踪、实测功耗行为和真实生产约束进一步校准模型；计划扩展至云边协同部署（大规模 DC + 边缘站点 + 资源受限边缘设备）。

## 研究启发与可借鉴点
1. **追踪驱动的抽象层级设计**：以硬件-模型配置文件为核心抽象层，在保持跨配置可比性的同时大幅降低模拟复杂度，值得借鉴用于其他系统级规划工具。
2. **模块化可替换接口**：各子系统（负载均衡、RE 建模、碳/水核算）实现为可替换接口，允许逐步提升局部保真度而无需重写整体框架，可作为系统设计范式参考。
3. **地理分布式碳感知路由策略**：引入加权评分 $S_i = w_c E_i + w_u U_i$（结合碳成本与利用率）的通用路由框架，可迁移至其他跨域资源调度场景。
4. **多目标权衡的场景化案例设计**：通过固定单一变量、对比多场景的方式揭示"能耗最优≠延迟最优"的决策分歧，为后续研究提供清晰的实验对照范式。
5. **与 Azure Inference Dataset 和 ServeGen 的整合**：无缝支持从聚合速率到查询级追踪的自动合成，降低了真实工作负载数据的获取门槛，可复用于其他推理研究。

## 关键术语表
- **InFactPlanner**：基于追踪数据的 LLM 推理数据中心可持续性分析框架，支持单站点和地理分布式的 what-if 部署规划。
- **PUE（Power Usage Effectiveness）**：数据中心总能耗与 IT 设备能耗的比值，衡量设施电力效率，典型值 1.2–2.0。
- **WUE（Water Usage Effectiveness）**：每 kWh 能耗对应的水消耗量（L/kWh），区分 onsite（站内冷却）和 offsite（发电间接）两部分。
- **TTFT（Time to First Token）**：从请求提交到返回第一个输出 token 的延迟，是 LLM 推理用户体验的关键指标。
- **TPS（Tokens Per Second）**：每秒生成的 token 数，衡量 LLM 推理吞吐量。
- **RES（Renewable Energy Source）**：可再生能源来源，本文聚焦太阳能光伏，支持解析和 ML 两种建模方式。
- **碳强度（Carbon Intensity, CI）**：单位电力的二氧化碳当量排放（gCO₂eq/kWh），随电网混合结构时空变化。
- **Inter/Intra Load Balancer**：数据中心间负载均衡器和数据中心内负载均衡器，负责将查询路由至合适服务器实例。
