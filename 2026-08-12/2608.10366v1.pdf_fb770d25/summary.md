# 论文速读：DSAgentBench: Can Agents Automate End-to-End Data-Science Workflows in Real Computer Environments?

## 一句话总结
本文提出了 **DSAgentBench**，首个在真实操作系统环境中评估 AI 智能体能否自动化执行端到端数据科学工作流的基准测试，涵盖数据获取、EDA、建模到可视化全流程；实验表明即使最强模型 Claude-4.6-Sonnet 仅达到 56.70% 任务成功率，暴露出当前智能体在工具编排、OS 落地和长程推理上的巨大能力缺口。

## 研究问题与动机
- **现有基准缺乏真实系统交互**：DS-1000、DABStep、MLAgentBench 等数据科学基准仅评估静态代码正确性，不要求智能体在真实 OS 中启动应用、管理依赖或与终端/IDE 交互；OSWorld、WebArena 等 GUI 基准则聚焦通用计算机操作而非分析推理。
- **端到端工作流的复杂性未被捕捉**：真实数据科学涉及多阶段（数据获取→EDA→特征工程→建模→可视化→报告）、多工具（VS Code、Jupyter、Chrome、SQLite）协调，现有基准仅覆盖孤立技能，无法反映长程规划与中间状态反馈的实际流程。
- **缺乏对分析正确性的确定性验证**：已有基准多依赖代码执行成功与否判断结果，而本文强调通过确定性 Python 评估器验证数值精度、可视化语义正确性与模型性能阈值，而非仅检查代码是否运行。
- **开源智能体能力鸿沟巨大**：实验揭示开源 GUI 智能体在真实桌面环境中几乎无法完成任何数据科学任务（成功率 <1%），与闭源模型存在显著差距，亟需系统性基准推动相关研究。

## 核心贡献（创新点）
1. **首个面向真实 OS 环境的数据科学工作流基准**：DSAgentBench 首次将数据科学任务置于具备文件系统、多应用和外部数据源的完整 Ubuntu 环境中执行，区别于仅评估代码生成的 DS-1000 或仅评估 GUI 操作的 OSWorld。
2. **覆盖完整数据科学生命周期的 275 个人工标注任务**：任务按数据获取、EDA、特征工程、建模、评估与部署、可视化六个阶段分布，每个任务配备环境配置与确定性评估函数，确保可复现性与语义正确性验证。
3. **混合观察模态与统一动作空间的公平评测协议**：支持纯截图（Screenshot）与截图+无障碍树（A11y Tree）两种观察模式，所有智能体通过统一的 PyAutoGUI 动作空间交互，排除接口特定优势，聚焦推理与落地能力对比。
4. **系统性错误分析与效率诊断**：通过对 604 条闭源模型轨迹和 150 条开源模型轨迹的手动分析，揭示落地错误（Grounding）、终端操作、代码语法、逻辑推理等不同失败根因的分布，并量化步数预算、工具使用与任务难度对成功率的影响。

## 方法详解
- **基准构建流程**：从 Kaggle、OpenML、SQLite、GitHub 等平台收集异构数据集（95.3% 表格数据）；两位标注员独立设计任务分类体系并编写 275 个任务，使用 GPT-5/Claude 4.5/Gemini 3 辅助润色表述但所有任务逻辑与评估器由人工定义；双重标注员验证确保 86% 初始一致率，最终全部达成一致。
- **环境架构（扩展 OSWorld）**：基于 OSWorld 框架在 Ubuntu VM 上预装 Python、VS Code、Jupyter Notebook、Chrome 及常见数据科学库；支持通过 Kaggle API、OpenML、直接 URL 和 SQLite 自动获取数据；屏幕分辨率为 1920×1080，每步捕获截图或截图+A11y Tree（通过 AT-SPI 提取 UI 元数据）。
- **任务形式化**：每个任务为三元组 $(\mathcal{C}_i, \mathcal{T}_i, \mathcal{V}_i)$，其中 $\mathcal{C}_i$ 定义初始系统状态（数据集、文件结构、已安装库、应用），$\mathcal{T}_i$ 为自然语言指令，$\mathcal{V}_i$ 为确定性 Python 评估器；评估器验证输出文件存在性、数值精度（容差 $\epsilon = 0.01$）、可视化语义（轴标签、标题、图例）及模型性能阈值（如 accuracy/F1 ≥ 0.7），仅约 10% 任务在确定性通过后调用 LLM 视觉评审（使用 Gemini-2.5-Pro 评 GPT-4o 输出以避免循环）。
- **智能体交互协议**：智能体在每个时间步 $t$ 接收观察 $o_t \in \mathcal{O}$，选择动作 $a_t \in \mathcal{A}$（鼠标点击/拖拽/滚动、键盘输入、WAIT/DONE/FAIL 控制命令），环境执行后转移到 $s_{t+1} = T(s_t, a_t)$；最大步数预算为 15 步（消融实验测试 30/50 步），任务超时时间为 1800 秒。

## 实验与结果
- **测试模型**：15 个闭源/开源智能体，包括 GPT-4o、GPT-5-mini、GPT-5、O4-mini、Claude Sonnet 4/4.5/4.6、Gemini-2.5-Pro、OpenAI CUA，以及 UI-TARS-2B/7B、GUI-OWL-7B、OpenCUA-72B、Jedi-3B/7B。
- **最强表现**：Claude-4.6-Sonnet 在 Screenshot+A11y Tree 设置下达到 **56.70%** 总体准确率（DA: 47.82%, EDA: 64.88%, FE: 56.75%, Model: 46.34%, Vis: 42.42%, Eval: 66.67%），GPT-5 次之（29.81%），其余闭源模型约 14–24%。
- **开源模型鸿沟**：所有开源智能体在纯截图设置下成功率均低于 **1%**（OpenCUA-72B 最高 0.73%），主要因落地错误占比 97–98%，无法正确打开或控制终端。
- **人类基线**：三位数据科学从业者（两名应用科学家+一名硕士）在相同环境下达到 **85.09%** 成功率。
- **关键发现**：
  - A11y Tree 对闭源模型有显著增益（Claude-4.6-Sonnet 从 50.55% 提升至 56.70%），但对部分模型效果有限。
  - 多阶段任务成功率（43.60%）远低于单阶段任务（59.66%）；硬难度任务（43.52%）显著低于中/简单难度。
  - Jupyter Notebook 任务（55.77%）优于 VS Code 任务（54.01%），归因于更少的环境/终端故障。
  - 步数预算从 15 增至 50 仅带来边际提升（24.54% → 25.81%），表明瓶颈不在行动次数而在落地、规划与分析推理能力。

## 相关工作脉络
- **DS-1000 / DABStep / MLAgentBench / DSBench / DSEval**：评估代码生成或子任务推理，但均在沙盒环境中静态执行代码，不涉及真实 OS 交互或多工具协调；本文填补端到端工作流评估空白。
- **DA-CODE**：较接近真实工作流，评估任务规划与多文件分析，但仍局限于笔记本沙盒，无 OS 访问或跨工具能力；本文扩展至完整桌面环境。
- **OSWorld / WebArena / VisualWebArena**：评估通用 GUI 操作与多步规划，但未针对数据科学的分析推理、数值验证与可视化合规性设计；本文定位数据分析专用基准。
- **ChartQA / Text2Vis / VisEval**：聚焦图表问答或生成，不涉及数据获取、清洗、建模等环节；本文覆盖完整生命周期。
- **UI-TARS / GUI-OWL / OpenCUA / CogAgent / ShowUI / JEDI**：开源 GUI 智能体在通用桌面任务上表现尚可，但在数据科学场景中因缺乏领域推理与工具链整合能力而几乎全败。
- **HumanEval**：仅评估函数级代码正确性，无数据分析或系统交互；本文强调端到端工作流与确定性结果验证。

## 局限性与未来方向
- **开源模型仅支持截图模态**：当前开源智能体未适配 A11y Tree 输入，无法评估其在全模态下的潜力；未来需推动开源模型对结构化 UI 元数据的支持。
- **错误分析样本有限**：仅手动检查 604 条闭源轨迹与 150 条开源轨迹，可能遗漏罕见失败模式；需更大规模自动化诊断。
- **可视化评估依赖少量 LLM 评审**：虽仅用于约 10% 任务且通过确定性门控，但主观质量判断仍存在偏差风险；可探索更细粒度的视觉度量。
- **环境局限于 Ubuntu**：虽基于 OSWorld 可移植至 Windows/macOS，但实验仅在一个 OS 上进行；跨平台鲁棒性待验证。
- **任务规模与复杂度平衡**：275 个任务对 OSWorld 级别基准属中等规模，未来可扩展至千级任务或引入更复杂的现实场景（如大规模数据湖、实时流处理）。

## 研究启发与可借鉴点
- **混合观察模态设计**：截图+A11y Tree 的组合为 GUI 智能体提供了视觉与结构化 UI 的双重信号，可在本团队计算机使用智能体研究中复用此设计以提升落地精度。
- **确定性+语义双阶段评估**：先用规则验证数值/文件/可视化元数据，再用 LLM 做质量判断，既保证稳定性又捕捉语义正确性；此范式可迁移至代码生成、数据分析等需结果验证的任务。
- **长程失败分解方法**：通过首次失败步骤（FF Step）、预算耗尽率、恢复率等指标量化智能体的探索效率与错误类型，为本团队调试复杂工作流提供诊断框架。
- **人类标注+LLM 辅助的任务生成管道**：专家设计任务逻辑与评估器、LLM 仅润色表述的流程确保任务质量与真实性，可借鉴用于构建其他领域基准。
- **开源模型能力鸿沟的启示**：开源 GUI 智能体在真实 OS 中几乎无法运行，提示需加强 grounding 训练与工具链集成；可考虑在本团队研究中引入 A11y Tree 或工具调用先验以提升开源模型表现。

## 关键术语表
- **DSAgentBench**：首个在真实操作系统环境中评估智能体自动化端到端数据科学工作流能力的基准测试，包含 275 个人工标注任务与确定性评估器。
- **OSWorld**：用于 benchmarking 多模态智能体在开放-ended 真实计算机环境中执行任务的基准框架，支持 Ubuntu/Windows/macOS。
- **A11y Tree（Accessibility Tree）**：通过 AT-SPI 提取的 UI 结构化元数据，包含元素角色、名称、边界框与交互状态，增强智能体对桌面界面的理解。
- **PyAutoGUI**：Python 自动化库，用于模拟鼠标点击、拖拽、滚动与键盘输入，本文所有智能体通过统一动作空间与之交互。
- **Deterministic Evaluator**：基于规则的 Python 评估脚本，验证输出文件存在性、数值精度、可视化标签与模型性能阈值，不依赖 LLM 判断。
- **First Failure (FF) Step**：任务轨迹中首次检测到错误的步数，用于分析智能体在哪个阶段发生失效（早期/中期/晚期）。
- **Data Science Lifecycle**：数据科学完整流程，包括数据获取（DA）、探索性数据分析（EDA）、特征工程（FE）、建模（Model）、评估与部署（Eval）、可视化与报告（Vis）。
- **Computer-Using Agent (CUA)**：OpenAI 开发的专用计算机使用智能体，通过屏幕截图与 GUI 操作完成桌面任务。

## 可复现要素
- **数据集**：275 个任务配套的真实数据集（来自 Kaggle、OpenML、SQLite、GitHub），均已预下载并随基准一同开源。
- **代码**：基准框架、评估脚本、环境配置与推理代码已开源至 https://github.com/vis-nlp/DSAgentBench。
- **关键超参**：屏幕分辨率 1920×1080；最大步数 15（消融实验用 30/50）；任务超时 1800 秒；temperature=0.1, top-p=0.9；最大输出 token 2000；动作延迟 2.0 秒。
- **开源状态**：论文明确声明所有代码、提示模板、环境配置与评估函数将随仓库发布；模型 API 调用配置使用各提供商默认设置。
