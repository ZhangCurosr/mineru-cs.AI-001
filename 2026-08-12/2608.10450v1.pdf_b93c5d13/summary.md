# 论文速读：Persistent Recursive Worlds Enable Autonomous Software Evolution

## 一句话总结
提出 EvoX Genesis 框架，将长周期软件开发的连续性从“持久化智能体”转移到“持久化软件项目”本身；通过“版本-路径”局域世界与递归委派机制，使有限生命周期的局部 agent 能够跨时间、跨模型持续积累并演进复杂系统（如从零构建 C 编译器、替换基础模型后继续开发、科学计算代码 Fortran→Rust 重写）。

## 研究问题与动机
- 长周期软件开发的核心难点在于：当贡献者（或 agent）更替时，如何保持接口一致性、技术债可控与历史可继承，而非单纯堆叠上下文窗口或延长单一 agent 运行时间。
- 现有 agentic 软件系统多依赖持久会话、共享记忆、管理器 agent 或 scratchpad 维持连续性，本质上将“持久性”绑定在 agent 进程上，导致 agent 生命周期与项目开发生命周期被错误等同。
- 传统版本控制与协作框架（如 Git 图、EvoGit）虽记录变更历史，但缺乏路径受限的局域委派与验证门控的层级接受机制，难以支撑深度递归的自主演进与跨代际续写。
- 科学软件重写场景要求实现语言/架构巨变的同时严格保留经审计的数值行为，现有生成式重写缺乏对“可验证科学语义”的强约束与追溯机制。

## 核心贡献（创新点）
1. **提出“持久递归世界”形式化模型**：以最小化“版本-路径”对 $(v, p)$ 定义局域世界，明确区分有限生命周期 agent 的局部代理、递归委派与已接受软件事件，将项目连续性从 agent 身份中剥离。
2. **实现 EvoX Genesis 架构**：有限寿命的管理员与执行器 agent 在路径作用域上下文中工作，仅当通过测试/约束/集成证据验证后由父节点提交为项目历史，支持跨路径递归委派而不立即推进版本。
3. **大规模从零构建验证**：使用 DeepSeek V4 Flash 在实现空白仓库中自主构建完整 C 编译器，产出 248,989 行代码，通过 c-testsuite 全量及多数 LLVM/Csmith 测试，累计 123.4 小时、仅花费 $44.38 token 费用。
4. **跨模型续写与科学代码重构验证**：在同一已完成的编译器世界后替换基础模型（GLM 5.2 → DeepSeek V4 Flash）仍能持续开发；同时完成 13 个 MESA 科学模块（约 13.9 万行 Fortran）至 Rust 的重写，数值结果 bit-exact 或接近，获得 1.55×–6.87× 中位加速。

## 方法详解
- **局域世界定义**：$w = (v, p)$，其中 $v$ 为已接受的软件版本（固定项目状态与可继承历史），$p$ 为仓库相对路径（划定 agent 的初始职责与修改作用域）。agent 可检视完整项目，但仅从 $p$ 开始行动并接收对应上下文。
- **有限生命周期与变更提议**：agent $A_i$ 接收目标 $g_i$ 后执行多轮 model-tool 交互，产出候选变更 $\Delta_i = A_i((v, p), g_i)$。其私有对话与 scratch 状态不传递给下一 agent，后续工作从接受的版本与路径重新实例化。
